## 1. 읽는 법

### 1-1. 케이스 번호

`TC-<영역>-<번호>`. 영역은 PRD 요구사항 묶음을 따른다.

| 영역 | PRD | 영역 | PRD |
| --- | --- | --- | --- |
| ACC | 5-1 계정·가입 | EVL | 5-7 채점·1차 합격 결정 |
| JOB | 5-2 공고·채점 기준 | RPT | 5-8 결과 공개·리포트 |
| DRF | 5-2 JOB-02 AI 공고 자동 만들기 | ADM | 5-9 관리자 결과 관리 |
| APP | 5-3 지원·사전 준비 | RES | 5-10 장애 이어가기 |
| INT | 5-4 AI 면접 진행 | CHT | 5-11 화면 이탈 |
| QST | 5-5 질문 만들기 | DAT | 10-2 보관·삭제 |
| COD | 5-6 코딩테스트 | SEC · NFR | 10-3 보안 · 성능·공정성 |

### 1-2. 테스트 종류

| 종류 | 뜻 | 도구 (TRD 13장) |
| --- | --- | --- |
| API | 서버 주소를 직접 불러 응답 코드·내용을 본다 | pytest + httpx |
| 처리 | 화면 없이 서버 안의 계산·판단 로직을 본다. AI 응답은 가짜(mock)로 넣는다 | pytest, mock LLM |
| E2E | 실제 브라우저로 처음부터 끝까지 눌러 본다 | Playwright |
| 시각 | 시각을 앞으로 넘겨 예약 작업을 본다 | freezegun (+ 3-3 주의) |
| 측정 | 기준 PC에서 숫자를 잰다. 통과·실패가 아니라 목표 대비 값 | 가짜 지원자 스크립트, NVML |
| 점검 | 설정·구성을 사람이 확인한다 | docker, 체크리스트 |

### 1-3. 우선순위

- **P1**: PRD 9장 완성 기준(AC)에 바로 걸린다. 하나라도 실패하면 "다 만들었다"고 볼 수 없다.
- **P2**: PRD 5장 요구사항이지만 AC에는 없다.
- **P3**: 안내 문구·표시 등 화면 품질.

### 1-4. 표시

- 🔀 문서끼리 달라 2장에서 정한 쪽을 따른 케이스
- ⏳ 임시 결정·추천안이라 팀이 바꾸면 같이 고칠 케이스

### 3-3. 시간이 걸리는 케이스를 돌리는 방법

- 서버의 "지금 시각"을 한 곳(시계 함수)에서만 읽게 만들어야 시각 케이스를 돌릴 수 있다. freezegun은 파이썬 시각만 바꾸고 **Redis 만료 시간과 Celery 예약 시각(eta)은 바꾸지 못한다** (5장 R-01).
- 15초·10분 같은 대기는 실제로 기다리지 않고 설정값을 줄이거나 시계를 넘겨서 본다. 줄인 값은 테스트 설정 파일에만 둔다.
- 마이크·카메라는 Chrome 실행 옵션 `--use-fake-device-for-media-stream`, `--use-file-for-fake-audio-capture=<답변.wav>`로 가짜 장치를 쓴다.

## 7. 구현하면 생길 문제와 대응

테스트를 실제로 돌릴 때 막힐 곳이다.

| # | 문제 | 영향 받는 케이스 | 대응 |
| --- | --- | --- | --- |
| R-01 | freezegun은 파이썬 시각만 바꾼다. Redis 만료(자리 10분)·Celery 예약(마감 시각)·브라우저 타이머는 그대로라 시각 케이스가 안 맞는다 | TC-RES-13·14, TC-INT-25~29, TC-RPT-03 | 서버가 시각을 한 함수에서만 읽게 만들고, 예약 작업은 "지금 실행" 테스트 주소나 명령으로 바로 부른다. Redis 만료 대신 DB 시각 비교로 판단 |
| R-02 | 헤드리스 Chrome에서는 전체 화면 API와 `visibilitychange`가 실제처럼 동작하지 않을 수 있다 | TC-CHT-01~07, TC-APP-25 | 화면 이탈 E2E는 창을 띄우는 모드(headed)로 돌리거나, 페이지에 이벤트를 직접 일으키는 방식을 같이 쓴다. 둘의 결과가 같은지 한 번 확인 |
| R-03 | 탭 닫기 때 sendBeacon이 가끔 서버에 못 간다. 그러면 규칙상 '장애'가 되어 AC-10이 실패로 보일 수 있다 | TC-RES-07, TC-RES-10 | 버그가 아니라 설계(지원자에게 유리하게)다. 두 케이스를 따로 두어 '기록 도착 → 응시 종료', '기록 막힘 → 장애'를 각각 확인한다 |
| R-04 | 진짜 AI는 같은 입력에도 답이 조금씩 달라 통과·실패가 흔들린다 | TC-EVL 전체, TC-QST, TC-INT-12~14 | 기능 케이스는 가짜 AI로만 돌리고, 진짜 AI의 품질은 측정 케이스(TC-NFR-05·06·07)로 따로 본다 |
| R-05 | 전체 응시 1건이 면접 약 25분 + 코딩 60분이다. 매번 끝까지 돌리면 너무 길다 | E2E 전체 | 빠른 묶음(답변 시간·코딩 시간을 테스트 설정으로 줄임)과 전체 묶음(기준 PC에서 실제 값)으로 나눈다. 줄인 값은 테스트 설정 파일에만 둔다 |
| R-06 | 가짜 마이크로 넣은 음성이 STT를 거치면 글자가 매번 조금 다르다 | TC-CHT-04, TC-INT-15 | 글자를 비교하는 케이스는 가짜 STT를 쓰고, 진짜 STT는 "글자가 나왔는지"만 본다 |
| R-07 | 바깥 전송 0건(AC-19)을 "없다"고 증명하기 어렵다 | TC-SEC-07·08 | 상자별로 바깥 접속을 시도하는 점검 스크립트 + 테스트 동안 호스트 방화벽 로그를 같이 남긴다 |
