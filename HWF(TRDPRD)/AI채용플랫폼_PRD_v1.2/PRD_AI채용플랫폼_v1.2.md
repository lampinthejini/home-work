# PRD — AI 채용 플랫폼 (모의면접 프로그램) v1.2

> 근거 문서: AI채용플랫폼_기술아키텍처_v0.7, AI채용 플랫폼 Mermaid v0.4, AI채용플랫폼_코딩테스트_v0.6, PRD v1.1에 대한 의사결정 피드백(2026-10-23)
> v1.0, v1.1에서 다룬 미확정 항목 외에, 이번 버전은 **평가 결과 공개 범위 정정**과 **공고 자동 생성 입력 방식/코딩테스트 토글 UI 변경**을 반영한다.

## v1.1 → v1.2 변경 요약
1. **평가 결과 공개 범위 정정**: v1.1에서는 모든 평가 결과(면접+코딩테스트)를 지원자에게 비공개로 설계했으나, 이는 의도와 다르게 과도하게 제한된 설계였다. **AI 모의면접 평가(점수/피드백)는 지원자에게 공개**하고, **코딩테스트는 정상 작동/비정상 작동 결과만 공개**하며 세부 평가(점수·근거)는 계속 관리자 전용으로 유지한다.
2. **코딩테스트 포함 여부 UI**: "토글" 대신 **체크박스**로 설정한다(공고 작성·수정 화면, 공고 자동 생성 화면 공통).
3. **공고 자동 생성 입력 방식**: 자유 서술 위주였던 입력 방식을 **선택형(직무/경력 등)과 짧은 단답형(회사 상황 등)을 혼합**한 방식으로 변경해 작성 부담을 줄인다.

---

## 1. 제품 개요
지원자가 공개 채용공고를 탐색하고 지원서를 제출하면, AI가 음성 기반 모의면접(질문 제시 → 답변 → 꼬리질문)을 진행하고, 이어서 직무별 코딩테스트(관리자가 공고별로 체크박스로 선택 적용)를 진행한 뒤 자동으로 평가 리포트를 생성한다. **면접 평가 결과(점수/피드백)는 지원자에게 공개되며, 코딩테스트는 정상/비정상 작동 결과만 공개되고 세부 평가는 채용담당자만 열람한다.** 기업 관리자는 AI 평가를 참고해 최종 채용 여부를 사람이 직접 결정한다.

## 2. 개발 목적
- 반복적인 1차 면접/서류 스크리닝에 드는 채용 담당자의 시간 부담을 줄인다.
- 고정된 루브릭과 가중치로 평가해 면접관·심사자 간 평가 편차를 줄인다.
- 코딩테스트에 AI 활용 과정(프롬프트, 검증, 디버깅)까지 평가 항목으로 포함해 실무에서 요구되는 "AI를 올바르게 쓰는 능력"을 함께 측정한다.
- 면접 평가는 지원자에게도 공개해 피드백으로서의 가치를 제공하고, 코딩테스트의 세부 평가 근거는 채용담당자만 열람해 평가 근거의 오남용·외부 유출을 막는다.
- 최종 채용 결정은 반드시 사람이 내리도록 해 AI 평가의 오남용·과신을 구조적으로 막는다.

## 3. 타깃 사용자
| 사용자 | 설명 | 주요 목표 |
|---|---|---|
| 지원자(구직자) | 공개 공고를 보고 지원하는 외부 사용자 | 공고 탐색 → 지원 → AI 면접 → 코딩테스트 응시 → 지원현황 및 면접 평가 확인 |
| 기업 관리자(채용 담당자) | 조직에 소속된 내부 사용자 | 공고 작성·관리 → 질문/가중치/코딩테스트 설정 → 지원자 심사(평가결과 전체 열람) → 최종 채용 결정 |

관리자 계정의 초대/승인 기능은 MVP 범위에서 비활성화한다(4.1, 9장 참조). 운영자(모델·정책 관리, 장애 대응) 역할은 이번 범위에서 관리자 역할에 포함하며, 세부 운영 권한 분리는 TRD에서 다룬다.

## 4. 핵심 기능
1. 공개 채용공고 탐색 및 지원
2. 로그인/회원가입 및 복귀 경로 보존 (`returnTo`)
3. 이력서 등록(PDF 업로드 또는 직접 작성) 및 확인
4. AI 모의면접: TTS 질문 제시 → STT 답변 전사 → 템플릿/RAG 기반 질문 생성 → 근거 기반 꼬리질문 (기본 10문항 + 꼬리질문 최대 4개, 총 최대 14문항)
5. 코딩테스트(면접 완료 후, **공고별 체크박스로 선택 적용**): 코드 에디터 + 자체 호스팅(온프레미스) LLM 채팅 + 격리 실행 환경
6. AI 자동 평가 및 리포트 생성 — **면접 평가(점수/피드백)는 지원자에게 공개**, **코딩테스트는 정상/비정상 작동 결과만 공개**, 세부 평가·근거는 관리자 전용
7. 관리자 대시보드: 공고관리, 지원자관리, 질문·가중치 설정, 일정/알림, 직무별 통계
8. 공고 자동 생성(AI) — 관리자가 몇 가지 질문(선택형+단답형)에 답하면 AI가 공고 초안 생성 (10장)
9. 비동기 일정/알림 (지원 마감 리마인더, 면접 일정 통보, 메일 발송)

### 4.1 관리자 계정 생성 (MVP 범위)
- 관리자 초대/승인 플로우는 **이번 버전에서 비활성화**한다. 관리자 계정은 운영자가 직접 발급하는 방식으로 임시 운영한다.
- 조직 내 관리자가 다른 관리자를 초대하고 승인하는 기능은 후속 버전 과제로 남긴다.

## 5. 사용자 흐름

### 5.1 지원자 흐름
```
공개 공고 목록 → 공고 상세 → 지원하기
  → (미로그인) 로그인/회원가입 모달 → 인증 성공 → 해당 공고 지원 흐름으로 복귀
  → 개인정보 동의(평가 결과 공개 범위 조항 포함) → 이력서 확인/등록 → 지원 접수
  → 마이크/카메라 환경 점검
  → AI 모의면접 응시(기본 10문항 + 꼬리질문 최대 4개, 총 최대 14문항) → 면접 완료
  → (공고에 코딩테스트 체크된 경우) 코딩테스트 응시 → 제출
  → 마이페이지에서 지원현황 확인
    - 면접: 평가 완료 시 점수와 AI 피드백(강점/개선점) 확인 가능
    - 코딩테스트: 정상 작동/비정상 작동 결과만 확인 가능(세부 평가는 비공개)
    - 최종 합격/불합격/보류 통지 확인
```
- 로그인 복귀 규칙: 상단 로그인으로 들어오면 공고 목록으로, "지원하기"를 누르다 로그인했으면 해당 지원 절차로, 관리자 계정으로 로그인하면 관리자 대시보드로 이동한다. `returnTo`는 허용된 내부 경로만 검증한다.
- **기본 순서는 "AI 면접 → 코딩테스트"로 확정**한다. 관리자가 공고별로 순서를 바꿀 수 있게 설계하되, 기본값은 면접을 먼저 진행한다.

### 5.2 관리자 흐름
```
관리자 로그인/권한 확인 → 대시보드
  → 공고 관리: 작성/수정(공고 자동 생성 버튼 포함) → 코딩테스트 포함 여부 체크박스 → 미리보기 → 게시/마감
  → 지원자 관리: 공고별 목록 → 지원자 상세(이력서/면접답변/코딩테스트 결과/AI 평가 전체) → 최종 채용 결정
  → 질문 설정: 수동 입력 또는 질문은행에서 자동 선택, 유형별 문항 수/평가 가중치 설정
  → 일정/알림: 캘린더 관리, 통보 메일 발송 이력 확인
  → 직무별 통계 조회
```

## 6. 기능 요구사항

### 6.1 로그인/회원가입 및 복귀 경로
- 미로그인 사용자가 "지원하기"를 클릭하면 로그인/회원가입 모달을 띄우고, 인증 성공 시 원래 하려던 지원 절차(`jobId` 보존)로 복귀한다.
- 신규 가입 시 이력서 등록 또는 건너뛰기를 선택할 수 있다.
- 관리자 계정으로 지원자 전용 기능(지원하기 등)에 접근하면 "지원자 권한 필요" 안내를 표시하고 차단한다.
- `returnTo`는 화이트리스트 기반 내부 경로만 허용해 오픈 리다이렉트를 방지한다.
- 관리자 계정은 초대/승인 절차 없이 운영자가 직접 발급한다(4.1절).

### 6.2 공고 탐색 및 지원
- 지원자는 비로그인 상태에서도 공고 목록/상세를 열람할 수 있다.
- 직무 필터·검색을 제공한다.
- 동일 공고에 중복 지원을 방지한다.
- 이력서가 이미 있으면 기존 이력서를 확인/수정, 없으면 PDF 업로드 또는 직접 작성 후 추출 결과를 확인/정정할 수 있어야 한다.

### 6.3 AI 모의면접
- 면접 시작 전 마이크/카메라 권한 확인 및 장치 점검을 거친다.
- 질문은 텍스트 표시와 동시에 TTS로 재생하며, TTS 종료 후 3-2-1 카운트 뒤 녹음을 시작한다.
- 답변은 제한시간 또는 제출 시점에 저장되고 STT로 전사된다. 전사 품질이 낮으면 재녹음/확인 요청으로 처리한다.
- **문항 수**: 기본 문항은 **10개 고정**이며, 유형별 분배는 인성 2 / 자소서 관련 2 / 기업 관련 2 / 직무 관련 4이다. 답변의 논리적 모순·모호함이 감지되면 꼬리질문이 기본 문항에 **추가로** 붙으며, 꼬리질문은 면접 전체에서 **최대 4개**까지 허용한다. 따라서 면접의 총 문항 수는 최대 10 + 4 = 14개다.
- 유형별 기본 문항 수와 꼬리질문 상한(기본값 4)은 관리자가 공고별로 조정할 수 있는 설정값으로 둔다.
- 질문은 관리자 수동 입력, 질문은행 선택, 기업 문서 기반 RAG 생성 중 하나로 공급되며, 실제 출제된 질문은 변경 불가 스냅샷으로 저장한다.
- 답변의 논리적 모순·모호함이 감지되고 꼬리질문 누적 개수가 4개 미만이면 근거 기반 꼬리질문을 생성한다. 4개에 도달하면 더 이상 꼬리질문을 생성하지 않고 다음 기본 질문으로 진행한다.
- 면접 상태는 `NOT_STARTED/READY/IN_PROGRESS/INTERRUPTED/SUBMITTED/REPORT_PENDING/REPORT_READY/FAILED`로 관리한다.
- **세션 재개**: 네트워크 중단 등으로 면접이 중단되면(`INTERRUPTED`), 마지막 저장 상태를 기준으로 **이어서 진행**할 수 있다. 처음부터 재응시하지 않는다.

### 6.4 코딩테스트 (면접 완료 후, 공고별 선택 적용)
- 기본 진행 순서는 **"AI 면접 → 코딩테스트"**이며, 관리자는 공고관리 화면에서 코딩테스트 포함 여부를 **체크박스**로 설정할 수 있다(v1.2 변경, 기존 토글 대체). 체크 해제된 공고는 코딩테스트 단계를 건너뛴다.
- LLM은 **자체 호스팅(온프레미스)으로 확정**한다. 외부 LLM API는 사용하지 않는다.
- 응시자는 코드를 직접 작성하거나 온프레미스 LLM 채팅 패널에 질문할 수 있다. AI 사용 자체는 감점 사유가 아니다.
- LLM 질문은 허용/보완 요청/반려로 분류되며, 반려되어도 시험 토큰 예산은 공지된 정책에 따라 차감될 수 있으나 실제 모델 사용량과는 별도로 기록한다.
- 시스템 오류·안전필터 오탐으로 반려된 경우 예산을 복원하고 감점하지 않는다.
- 제출된 코드는 변경 불가 스냅샷으로 저장되고, 격리된 실행 환경에서 공개 테스트(응시 중)와 비공개 테스트(제출 후)를 수행한다.
- 시험 토큰이 소진되어도 코드 편집·실행·제출은 계속 허용한다.
- 반려 누적에 따른 감점은 "프롬프트 및 AI 활용 판단(15점)" 항목 내 최대 3점으로 제한하며, 자동 산정값은 확정 점수가 아니라 관리자 검토 대상이다(1회 0점 / 2회 0.5점 / 3회 1.5점 / 4회 2.5점 / 5회 이상 최대 3점, 누적).
- **토큰 예산/반려 정책의 구체적인 수치(예: 반려 시 차감량)는 이번 버전에서 확정하지 않으며, 실제 운영 전 모의시험을 통해 검증한다**(9장).
- 실제 정답·비공개 테스트 내용은 어떤 경우에도 LLM 프롬프트나 검색 문서에 노출하지 않는다.

### 6.5 평가 및 리포트
- 면접 평가는 고정 루브릭(논리성/전달력/전문성/내용 관련성)으로 질문별 채점 후 공고별 버전 고정 가중치로 합산한다.
- 코딩테스트 평가는 정확성 40 / 코드 품질 20 / 검증·디버깅 20 / 프롬프트·AI 활용 판단 15 / 설명·근거 5(합계 100, 초안)로 산출한다.
- 면접 점수와 코딩테스트 점수는 별도로 기록하고, 관리자 화면에서 통합 조회할 수 있다.
- AI 평가 결과에는 근거 인용과 신뢰도/검토 필요 표시를 포함한다.
- **평가 결과 공개 범위 (v1.2 변경)**:
  - **AI 모의면접**: 항목별 점수와 AI 피드백(강점/개선점)을 평가 완료(`REPORT_READY`) 시점에 **지원자에게 공개**한다. 단, 평가 근거 인용 원문과 신뢰도/검토 필요 표시는 관리자 전용으로 유지한다.
  - **코딩테스트**: 지원자에게는 **정상 작동/비정상 작동**(공개·비공개 테스트 통과 여부 수준)만 공개한다. 정확성/코드품질/검증·디버깅/프롬프트 활용 판단 등 세부 점수와 근거는 **관리자만 열람**한다.
  - 지원자는 마이페이지에서 위 공개 범위에 해당하는 내용과 최종 채용 결과(합격/불합격/보류) 통지를 확인할 수 있다.
- 최종 채용 여부(합격/불합격/보류)는 AI가 자동 결정하지 않고 관리자가 결정하며, 결정·통지 이력을 기록한다.

### 6.6 관리자 공고/질문/평가 관리
- 공고 작성/수정, 임시저장/템플릿, 지원자 화면 미리보기, 게시/마감/삭제 정책을 제공한다.
- 질문은 수동 입력 또는 빈 슬롯 자동 선택으로 구성하고, 유형별 문항 수와 제한시간을 설정할 수 있다.
- 평가 항목별 가중치를 공고 단위로 설정할 수 있다.
- 캘린더에서 면접 일정을 추가/수정할 수 있다.
- 직무별 통계를 상세히 조회할 수 있다.

### 6.7 비동기 일정/알림
- 지원 마감 임박 시 미완료 지원자에게 리마인더를, 공고 마감 하루 전 관리자에게 알림을 발송한다.
- 일정 생성/변경 시 수락/조율 링크를 포함한 통보를 발송한다.
- 발송 실패 시 재시도하며, 중복 발송은 방지한다.

### 6.8 공고 자동 생성
10장에서 상세 설계와 리스크를 다룬다.

## 7. 비기능 요구사항

### 7.1 성능 (초안 — 부하테스트 전 확정값 아님)
- API 응답 목표: 일반 API p95 300ms 이내(초안). 실제 목표치는 동시 사용자 수 확정 후 조정한다.
- LLM 추론·STT/TTS·코드 실행은 동기 API 요청과 분리된 큐/워커에서 처리한다.
- **온프레미스 LLM 현재 제약**: 현재 개발/시험 환경의 GPU는 VRAM 6GB이다. 이 환경에서는 소형/경량 양자화 모델 1종, 사용자당 동시 추론 1건 수준으로 MVP를 구성한다. **실무(실제 서비스) 환경에서는 더 큰 GPU로 확장 가능**하며, 모델 크기·동시성·응답 속도 목표는 확장된 하드웨어 기준으로 재산정한다.
- MVP 기준: 코딩테스트 언어 1종, 실행 동시성 제한.

### 7.2 보안
- 모든 통신 HTTPS, 비밀번호는 Argon2 등 안전한 해시로 저장한다.
- 서버 측 RBAC 및 조직 범위(`organization_id`) 검증을 모든 API/쿼리에 적용한다(화면 숨김만으로 대체하지 않는다).
- `returnTo`는 오픈 리다이렉트 방지를 위해 내부 경로만 허용한다.
- 면접 음성/대화 전사, 코딩테스트 채팅 내용 등 개인정보가 포함될 수 있는 데이터는 접근통제·암호화·감사 로그를 적용한다.
- **평가 데이터 접근 제어 (v1.2 변경)**: 면접 평가 점수·AI 피드백은 지원자 본인에게 공개 API로 제공한다. 코딩테스트 세부 평가(점수·근거)와 평가 근거 원문·신뢰도 표시는 관리자 권한을 가진 사용자만 조회 가능하도록 접근 제어한다(지원자 본인도 조회 불가).
- 코드 실행 환경은 네트워크 차단, CPU/메모리/시간 제한, 비특권 사용자, 임시 파일 정리, 동시성 제한을 적용한다.
- 코딩테스트 LLM에는 정답·비공개 테스트·숨은 채점 기준을 절대 노출하지 않는다.

### 7.3 안정성
- **세션 재개**: 면접/코딩테스트 세션 중 네트워크가 중단되면 마지막 저장 상태를 기준으로 이어서 진행할 수 있도록 지원한다. 처음부터 다시 시작하지 않는다.
- 토큰 원장(예산 차감/복원), 평가 변경 등 민감한 상태 변경은 append-only 이벤트로 기록하고 삭제하지 않는다.
- 동일 요청 ID의 중복 전송은 멱등 처리한다.
- 비동기 작업(리포트 생성, 메일 발송, 평가)은 재시도와 상태 추적(`status`, `attempts`, `error_code`)을 갖춘다.

### 7.4 개인정보/공정성
- 이력서·음성·대화·코드 데이터는 목적별 수집·고지·동의를 거치고 보존기간·삭제 절차를 둔다.
- **개인정보 활용 동의서에 다음 내용을 명시해 지원자에게 사전 고지한다(v1.2 변경)**: "AI 면접의 평가 결과(점수, AI 피드백)는 본인에게 공개됩니다. 코딩테스트는 정상 작동/비정상 작동 결과만 공개되며, 세부 평가 점수와 근거는 채용담당자에게만 제공됩니다."
- 시선/감정/음성 특성만으로 부정행위나 성격·적합성을 단정하지 않는다.
- 코딩테스트 LLM 함정 시나리오는 난이도·노출·모델 버전을 고정하고 사전 QA를 거쳐 공정성을 검증한다.
- 지원자에게는 AI가 불완전하거나 틀린 답을 줄 수 있다는 점과 감점 정책을 사전에 고지한다.

### 7.5 개발 환경 요구사항 (제안 — 정확한 버전 고정은 TRD에서 확정)
- 백엔드: Python 3.12 기반 venv, FastAPI + Pydantic 2, SQLAlchemy 2 + Alembic
- DB: PostgreSQL 17 + pgvector 확장
- 비동기 처리: Redis + Celery
- AI 오케스트레이션: LangChain 1.x + LangGraph 1.x
- 프런트엔드: Next.js 16 / React 19 / TypeScript, 코드 에디터는 Monaco Editor
- 온프레미스 LLM 서빙: Ollama(MVP, GPU 6GB 환경 기준 소형 양자화 모델) — 실무 환경 확장 시 vLLM 및 더 큰 모델 검토
- 코드 실행: 격리된 컨테이너 또는 마이크로VM 기반 실행기
- 위 패키지/버전은 근거 문서의 권장 스택을 따른 제안이며, 실제 설치 목록·버전 고정은 TRD의 기술 스택 절에서 확정한다.

## 8. 성공 지표
- **엔드투엔드 완결성**: 지원 → AI 면접 → 코딩테스트 → 평가 리포트 → 관리자 심사 → 채용 결정까지 중단 없이 흐르는 비율
- **면접 단계 오류율**: STT 전사 실패/재녹음 발생률, 세션 중단율, 중단 후 재개 성공률
- **코딩테스트 공정성**: LLM 함정 시나리오가 의도대로 작동(응시자가 오류를 발견·수정하는 비율), 오탐 반려 발생률
- **평가 리포트 처리 시간**: 면접/코딩테스트 제출 후 리포트 `REPORT_READY`까지 소요 시간
- **관리자 심사 효율**: 지원자 1명당 관리자 심사 소요 시간(AI 평가 도입 전후 비교)
- **지원자 피드백 만족도(v1.2 신규)**: 면접 평가 공개 후 지원자의 피드백 품질 체감도(설문 등으로 측정)
- **공고 자동 생성 활용도**: 자동 생성 기능 사용률, 생성 후 관리자 수정 비율(과도한 수정이 필요하면 품질 문제로 간주)

## 10. 추가 제안 기능: 공고 자동 생성
CLAUDE.md 추가 요구사항에 명시된 기능으로, 근거 문서 3종에는 없는 신규 플로우라 직접 설계했다.

### 10.1 흐름
```
관리자: 공고 관리 화면에서 "공고 자동 생성" 버튼 클릭
  → 질문 응답(v1.2 변경: 선택형 + 단답형 혼합)
     - 선택형: 직무, 경력 연차, 고용 형태 등 — 드롭다운/버튼 선택
     - 단답형: 회사 상황 등 — 짧은 한두 줄 입력(긴 자유 서술 textarea 대신)
     - 코딩테스트 필요 여부 — 체크박스
  → AI가 공고 초안 생성(제목/설명/자격요건/우대사항, 코딩테스트 체크박스 자동 세팅)
  → 관리자 검토(미리보기) 화면에서 확인·편집
  → 게시
```

### 10.2 기능 요구사항
- **입력 방식(v1.2 변경)**: 모든 항목을 자유 서술로 받지 않는다. 직무/경력/고용형태처럼 정형적인 항목은 선택형(드롭다운, 버튼 선택)으로 받고, 회사 상황처럼 서술이 필요한 항목만 짧은 단답형 입력(1~2줄)으로 받아 작성 부담을 줄인다.
- 자동 생성은 초안 생성까지만 수행한다. 게시 버튼 자체를 막지는 않지만, **검토를 건너뛰고 바로 게시하려 할 때 주의 메시지(예: "AI 생성 초안을 검토하지 않았습니다. 그대로 게시하시겠습니까?")를 표시**해 관리자가 인지하도록 한다. 게시를 강제로 차단하지는 않는다.
- 코딩테스트 필요 여부 질문에 대한 답은 6.4절의 공고별 **체크박스** 기본값으로 반영한다(v1.2 변경, 기존 토글 대체).
- 생성 이력(입력 질문/답변, 생성된 초안, 모델 버전)을 기록해 추후 품질 검증에 활용한다.

### 10.3 장점
- 비전문 관리자도 일관된 형식·품질의 공고를 빠르게 작성할 수 있다.
- 공고 작성 소요 시간을 줄인다.
- 선택형+단답형 혼합 입력으로 자유 서술에 대한 부담을 낮춰 입력 완료율을 높인다(v1.2).

### 10.4 리스크 및 대응
- **사실과 다른 내용 생성(hallucination)**: 회사 상황 입력이 부실하면 근거 없는 내용이 들어갈 수 있다 → 관리자 검토 단계를 권장하고 검토 여부를 추적한다.
- **차별적/법적 문제 문구 포함 가능성**: 자격요건 작성 시 연령·성별 등 차별적 표현이 생성될 수 있다 → 생성 후 민감 문구 필터링 또는 체크리스트 제공을 권장한다.
- **과신으로 인한 검토 생략**: 관리자가 초안을 그대로 게시할 위험 → **게시를 차단하지 않고, 검토 전 게시 시도 시 주의 메시지만 노출**한다.
