# 코딩테스트 모듈 v0.6 — 설계 및 평가 기준

## 목적
코드 작성 능력뿐 아니라 LLM 프롬프트 작성, 생성물 검증, 오류 수정, 불확실성 처리, 근거 제시를 평가한다. AI 사용은 허용하며, 사용 사실만으로 자동 감점하지 않는다.

## 사용자 화면
- 문제 설명 / 제약 조건 / 남은 시간
- 코드 에디터 및 실행 결과
- 온프레미스 LLM 대화 패널 (프롬프트, 응답, 복사/삽입 기록)
- 검증 근거 또는 수정 사유 메모 (선택적; 평가 항목이라면 사전 고지)
- 제출 버튼 / 자동 저장 상태 / 연결 복구

## 함정 시나리오
- 제한된 문서 또는 일부 맥락만 제공
- 오래된 API 사용 예시 또는 경계조건 오류가 있는 응답
- 모호한 문제에서 확인 질문을 유도하는 불완전한 요구
- 실제 정답 및 비공개 테스트는 모델 프롬프트/검색 문서에 절대 포함하지 않음
- 응시자에게 AI가 불완전하거나 틀린 답을 제공할 수 있음을 사전 고지
- 시나리오별 난이도/노출/모델 버전 고정, 사전 QA 및 동등성 검토
- 고의적 오류를 모델 출력에 매번 안정적으로 강제하기 어렵다. 재현성 높은 테스트는 고정 응답 시나리오나 통제된 검색 자료를 사용

## 평가 예시 (초안, 합계 100)
| 항목 | 점수 | 근거 |
|---|---:|---|
| 기능 정확성 / 숨은 테스트 | 40 | 정답률, 경계조건 |
| 코드 품질 / 안정성 | 20 | 구조, 예외 처리, 성능 |
| 검증 및 디버깅 | 20 | 실패 재현, 오류 수정, 재검증 |
| 프롬프트 및 AI 활용 판단 | 15 | 명확한 요구, 검증 질문, 선택적 채택 |
| 설명 및 근거 | 5 | 설계 선택 설명 |

**주의:** AI 사용 여부 자체에 고정 감점을 주지 않는다. 무비판적 채택으로 발생한 오류는 정확성/검증 항목에서 반영한다. 동일 결과에 중복 감점을 피한다. 관리자에게 점수 근거와 이력 열람을 제공한다.

## 이벤트 / 저장 예시
- test_sessions: session_id, applicant_id, job_id, problem_version, scenario_version, model_version, start/end/status
- llm_messages: session_id, turn_id, role, content, model_version, token_count, latency_ms, created_at
- editor_events: session_id, event_id, event_type, diff_or_snapshot_ref, source_tag, created_at
- code_runs: run_id, session_id, snapshot_ref, test_result, runtime_ms, created_at
- submissions: submission_id, session_id, final_snapshot_ref, submitted_at
- assessments: submission_id, rubric_version, scores, rationale, reviewer_id

채팅 내용에는 개인정보/비밀정보가 포함될 수 있으므로 접근통제, 보존 기간, 삭제 정책, 감사 로그, 암호화를 설계한다. 코드 실행기는 컨테이너/마이크로VM 격리, 네트워크 차단, CPU/메모리/시간 제한, 비권한 사용자, 임시 파일 정리, 동시성 제한을 적용한다. 브라우저의 키 입력을 무차별 기록하지 말고 의미 있는 편집 이벤트와 주기적 스냅샷을 저장한다.

## 부하 / 운영
- 가장 무거운 부분: 온프레미스 모델 추론 GPU 메모리와 동시 생성 요청, 코드 실행 격리 환경
- 중간: 자동 테스트, LLM 답변 스트리밍, 평가 작업
- 상대적으로 가벼움: 메타데이터/프롬프트 로그/코드 스냅샷 저장 (다만 보존량 증가)
- MVP: 한 종류의 언어, 소형/중형 모델 하나, 1인당 동시 추론 1건, 토큰 상한, 작업 큐, 실행 동시성 제한, 제출 후 비동기 채점
- 정확한 GPU 규모는 모델 파라미터, 양자화, 컨텍스트 길이, 응시자 수, 초당 토큰 목표를 정한 뒤 부하 테스트로 산정

## 기존 채용 플로우와 연결
공고 지원 → 서류 검토 → 코딩테스트 배정(직무별 선택) → 코딩테스트 응시/평가 → AI 면접(순서는 기업 설정 가능) → 관리자 최종 판단. 코딩테스트 점수와 AI 면접 점수는 별도 기록하고 통합 조회한다.


## LLM 질문 반려 및 시험 토큰 예산 정책 (v0.6 추가)

### 원칙
- 응시자는 직접 코딩하거나 온프레미스 LLM에 질문할 수 있다. AI 사용 자체는 감점 사유가 아니다.
- 질문은 허용·보완 요청·반려로 처리한다. **반려되어도 시험 토큰 예산은 차감**할 수 있으나, **실제 모델 사용량과 시험 예산 차감량은 별도로 기록**한다.
- 사전 공지된 정책에 따른 지원자 책임의 반복 반려에 한해 프롬프트·AI 활용 판단 항목 내에서 소폭 감점한다. 자동 감점은 확정 점수가 아니라 검토 대상이다.
- 시스템 오류, 안전 필터 오탐, 타당한 검증·정정 질문, 장애로 인한 반려는 감점하지 않으며 예산을 복원한다.
- AI 답변에 의도적으로 불완전한 문맥이나 검증 가능한 오류가 포함될 수 있음을 사전 고지하고, 오류를 발견·수정·설명하는 역량을 평가한다. 응시자에게 숨겨진 채점 기준이나 정답을 모델에 제공하지 않는다.

### 질문 처리 유형
| 유형 | 예시 | 처리 | 시험 예산 | 점수 처리 |
|---|---|---|---|---|
| 정상 질문 | 특정 함수의 시간복잡도 검토 | 답변 | 입력+출력 사용량 차감 | 감점 없음 |
| 모호한 질문 | '이거 고쳐줘' (코드·오류 정보 없음) | 보완 요청 또는 반려 | 공지된 차감 규칙 적용 | 반복·귀책 확인 시 후보 |
| 정답 전체 요청 | '정답 코드를 전부 작성해줘' | **시험 모드 정책에 따라 허용 또는 제한** | 정책대로 차감 | 요청 자체로 자동 감점 금지 |
| 반복 무의미 질문 | 동일한 무관 질문 반복 | 제한/반려 | 공지된 차감 규칙 적용 | 반복 시 소폭 감점 후보 |
| 오류 검증 | '이 코드의 반례를 찾아줘' | 허용 | 실제 사용량 차감 | 검증 근거 있으면 가점 가능 |
| 시스템 오탐/장애 | 유효한 질문이 잘못 차단됨 | 재처리/복구 | 차감 취소·복원 | 감점 없음 |

### 토큰 회계 및 정책 검사
1. 요청 수신 시 질문·시각·세션 ID·요청 ID를 저장한다. 중복 전송은 동일 요청 ID로 멱등 처리한다.
2. 시험 예산 잔량과 질문 정책을 확인한다. 차감 방식은 응시 전 공개한다.
3. **정책 검사 이전에 모델 추론이 실행되지 않았다면 실제 LLM 추론 토큰은 0**으로 기록한다. 별도 정책 분류 모델을 쓴다면 해당 모델 사용량은 시스템 비용으로 별도 계상한다.
4. 허용 요청은 실제 입력/출력 토큰을 계량해 시험 예산에 반영한다. 스트리밍 취소·실패는 실제 사용량과 환불 규칙을 기록한다.
5. 반려 요청은 정책에 따라 `입력 토큰 상당량 + 고정 시험 수수료` 등으로 차감할 수 있다. 예: 고정 100 시험 토큰은 **조정 가능한 예시값**이다.
6. 장애·오탐으로 반려되면 차감 취소 이벤트를 추가하여 잔액을 복원한다. 원본 사용·차감 이벤트는 삭제하지 않는다.
7. 예산 부족 시 LLM 질문만 중지하고, 코드 편집·실행·제출은 계속 허용한다.

### 감점 기준 (초안: 평가표 100점 내 포함, 추가 감점 아님)
- 대상: 기존 **프롬프트 및 AI 활용 판단 15점** 중 최대 **3점**.
- 첫 귀책 반려: 경고, 감점 0점. 두 번째: 0.5점. 세 번째부터: 건당 1점. **누적 최대 3점**.
- 예: 1회 0점 / 2회 누적 0.5점 / 3회 누적 1.5점 / 4회 누적 2.5점 / 5회 이상 최대 3점.
- 동일 원인 반복, 정책 설명의 명확성, 합리적 재질문 여부를 검토한다. 개선된 프롬프트와 오류 검증은 해당 항목의 긍정적 증거로 기록할 수 있다.
- 이 규칙은 운영 전 모의시험·직무별 난이도 검증 후 확정하고, 시험 시작 전 지원자에게 공개한다. **AI 사용 횟수나 토큰 사용량만으로 감점하지 않는다.**
- 자동 채점 결과는 근거·반려 사유·이의 제기 상태와 함께 관리자에게 표시하고, 최종 확정은 사람이 한다.

### 추가 데이터 모델
- `llm_requests`: request_id, session_id, prompt, policy_version, disposition(allowed/clarify/rejected), rejection_code, responsibility(applicant/system/undetermined), created_at
- `token_ledger`: ledger_id, request_id, event_type(reserve/charge/refund/adjust), exam_tokens_delta, actual_input_tokens, actual_output_tokens, policy_model_tokens, balance_after, created_at
- `llm_messages` 확장: request_id, response_status, model_version, scenario_version, latency_ms, response_text_ref
- `penalty_reviews`: request_id, rubric_version, proposed_penalty, final_penalty, reviewer_id, review_reason, appeal_status
- 시험 세션 확장: `exam_token_budget`, `exam_token_balance`, `question_policy_version`, `penalty_policy_version`
- 모든 원장 변경은 추가 기록 방식으로 처리하고, 중복 요청 및 재시도에 대한 중복 차감을 방지한다.

### 화면 및 운영 요구
- 질문창에 남은 시험 토큰, 반려 가능 사유, 감점 정책, 이의제기 방법 표시.
- 반려 시 이유·차감량·재질문 가이드 제공. 검증 목적의 질문을 차단하지 않도록 정책 테스트 수행.
- 관리자 화면에 질문별 허용/반려/보완 상태, 실제 사용량, 시험 예산 원장, 감점 후보, 오탐 정정 내역 표시.
- 반려·차감·감점 정책은 문제·시험별 버전으로 고정하고 시험 중 소급 변경하지 않는다.
