# 활동 다이어그램 (UML Activity Diagram)

AI 1차 채용면접 플랫폼의 기능별 동작 흐름을 UML 활동 다이어그램으로 정리한 문서다.
현재 구현 코드(`huge/`, 2026-11-11 기준)를 보고 그렸다. 설계 문서와 다른 부분은 `huge/CONFLICTS.md` 를 따른다.

## 읽는 법

| 기호 | 뜻 |
|---|---|
| ● 검은 원 | 시작 |
| ◉ 테두리 있는 원 | 활동 끝 (전체 흐름 종료) |
| ⊗ X 표시 원 | 흐름 끝 (이 갈래만 끝남) |
| 둥근 사각형 | 행동 |
| ◇ 마름모 | 판단(갈림) 또는 합류. `[조건]` 은 그 길로 가는 조건 |
| 굵은 가로 막대 | 분기(fork): 아래 흐름들이 동시에 진행 |
| 모래시계 | 시간 이벤트 |
| 접힌 종이 | 메모 |
| 세로 칸(swimlane) | 그 행동을 맡은 쪽 |

PNG 는 보기용이다. 아래 Mermaid 코드는 편집용이며, 같은 흐름을 담지만 칸 배치와 모양은 PNG 와 다르게 그려진다.

## 01. 로그인

![01. 로그인](01_로그인.png)

- 입력값이 비면 서버에 보내지 않는다.
- 인증 실패는 관리자 계정 실패 횟수와 IP 실패 횟수로 따로 센다. IP 차단 중이면 429 를 돌려준다.
- 성공하면 세션을 DB 에 저장하고 HttpOnly 쿠키를 준다. 이동 경로는 서버가 역할에 따라 정한다.
- 세션은 2시간 동안 활동이 없으면 끝난다. 비밀번호 변경·재설정 때는 다른 기기의 세션도 지운다.

## 02. 지원서 작성 (지원 → 동의 → 이력서 제출)

![02. 지원서 작성 (지원 → 동의 → 이력서 제출)](02_지원서작성.png)

- 지원 요청은 게시 상태·접수 기간·직무·중복 지원을 검사한다. 작성 중인 지원이 있으면 그 건을 이어 쓴다.
- 필수 동의 5개와 동의 문구 버전이 맞아야 저장한다.
- 파일 업로드는 비동기로 추출하고, 지원자가 결과를 확인·수정한 뒤 제출한다.
- 제출하면 drafting → ready 가 되고, 평가 기준 버전이 고정되며, 질문 생성(03)이 시작된다.

## 03. 면접 질문 생성 (질문 구성 그래프)

![03. 면접 질문 생성 (질문 구성 그래프)](03_면접질문생성.png)

- 기본 질문 10개를 순서표대로 한 자리씩 채운다.
- 예시 질문을 pgvector 로 찾고, LLM 이 질문 1개를 만든다. 형식·근거·베낌·중복 검사를 통과해야 채택한다.
- 재생성 한도(3회)를 넘기거나 장애·시간 초과가 생기면 질문은행 질문으로 대신한다. 대체 사유를 기록한다.
- 10개가 모두 차면 ready 로 바꾸고 TTS 음성을 미리 만든다.

## 04. AI 면접 진행

![04. AI 면접 진행](04_AI면접진행.png)

- 환경 점검 결과는 15분 동안 유효하다. 시작할 때 1회 응시·접수 기간·점검·동시 응시 자리(기본 2)를 확인한다.
- 질문 → 답변 녹음 → STT → 저장 → 꼬리질문 판단을 기본 질문 10개 동안 반복한다.
- 꼬리질문은 기본 질문 하나에 최대 1개, 면접 전체에 최대 4개다.
- 끝나면 코딩테스트 적용 공고는 coding(07), 아니면 completed 가 되고 채점(08)에 들어간다.
