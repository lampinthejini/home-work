# 이용자 가이드 — 관리자용

공고를 만들고, 지원자의 AI 면접 결과를 확인하고, 운영 상태를 관리하는 방법입니다.
(2026-11-10 기준 프로그램 동작에 맞춰 썼습니다.)

---

## 1. 처음 로그인

1. 관리자 계정은 설치할 때 한 개 만들어집니다(`python -m app.manage init`).
2. 첫 로그인 때 **초기 비밀번호 변경** 화면이 나옵니다. 바꾸기 전에는 다른 화면으로 갈 수 없습니다.
3. 로그인하면 **공고 관리** 화면으로 갑니다. 왼쪽 메뉴는 다음과 같습니다.

| 메뉴 | 하는 일 |
|---|---|
| ▤ 공고 관리 | 공고 만들기·수정·게시·마감·삭제 |
| ▥ 지원자 | 공고별 지원자 목록, 점수, 상세 리포트, 비교 |
| ▦ 다음 전형 | 1차 합격자 목록과 연락처 |
| ▨ 질문 관리 | 면접 질문은행 검토 |
| ▧ 대시보드 | 통계, 운영 현황(평가 지연·메일 실패·로그인 차단) |
| ⚙ 운영 설정 | 동시 면접 상한 |

> 관리자와 지원자는 **다른 브라우저**(예: 관리자는 Edge)로 쓰는 것을 권합니다. 같은 브라우저에서는 로그인이 섞입니다.

---

## 2. 공고 만들기

**공고 관리 → [새 공고 만들기]** 에서 두 가지 중 고릅니다.

### ✨ AI로 공고 자동 만들기

1. 회사 소개, 하는 일, 원하는 사람 등 질문에 짧게 답합니다(코딩테스트 사용 여부 포함).
2. AI가 초안을 씁니다. 보통 수십 초 걸리고, 다른 화면에 가 있어도 됩니다. 화면에는 지금 하는 일이 **참고 공고 찾기 → 초안 작성 → 표현 점검·고쳐 쓰기** 순서로 보입니다.
   - 같은 직무의 예전 공고가 있으면 용어와 말투만 참고합니다(문장을 그대로 옮기지 않습니다).
   - 초안을 다 쓴 뒤 칸마다 차별로 보일 수 있는 표현이나 예전 공고를 베낀 문장이 있는지 보고, 있으면 그 칸만 한 번 다시 씁니다.
3. 초안은 **임시 저장** 상태로 만들어집니다. 반드시 읽고 고친 뒤 게시합니다. 1단계 위쪽에 AI가 무엇을 고쳤는지(처리 기록)가 나옵니다.
4. 실패하면 **[다시 시도]** 하거나 **[직접 작성으로]** 넘어갑니다.

**마음에 안 드는 칸만 AI에게 다시 쓰게 하기** — AI 초안 공고의 1단계에는 **'AI에게 한 칸 다시 쓰게 하기'** 상자가 있습니다.

1. 다시 쓸 칸(부서 소개·주요 업무·자격 요건·우대 사항 등)을 고르고, 원하는 점을 적습니다(예: "더 짧게", "신입도 지원할 수 있게").
2. 보내면 그 칸만 새 글로 바뀝니다. 다른 칸은 그대로입니다.
3. 바뀐 글은 **아직 저장되지 않았습니다.** 읽어 보고 **[임시저장]** 을 눌러야 저장됩니다.
4. 게시한 공고에는 쓸 수 없습니다.

> AI 초안 진행 상태는 서버 메모리에 있어서, 그사이 서버가 다시 켜지면 '실패'로 보입니다. 다시 시도하면 됩니다.

### ✍ 직접 작성 (3단계)

**1단계 — 공고 내용**
- 제목, 직무, 회사 소개, 하는 일, 자격 요건, 우대 사항, 고용 형태, 근무지, 모집 인원, 접수 시작·마감, 문의 이메일
- **차별로 보일 수 있는 표현**(나이·성별·혼인·외모·신체·출신·종교)을 쓰면 노란 안내가 뜹니다. 저장을 막지는 않지만 고치는 것을 권합니다.
- 결과는 **마감 다음 날 10:00** 에 공개됩니다.

**2단계 — 평가 기준**

| 항목 | 규칙 |
|---|---|
| ① 평가 항목 가중치 | 5% 단위, 항목마다 5% 이상, **합계 100%**. 안 맞으면 "합계가 95%입니다. 100%로 맞춰 주세요" |
| ② 코딩테스트 | 켜면 AI 면접 뒤 코딩테스트(Python 3 · 2문항 · 60분). 반영 비중은 10% 단위 |
| ③ 1차 합격 기준 점수 | 0~100점. 칸을 비우면 "합격 기준 점수를 입력해 주세요" 가 나오고 다음으로 갈 수 없습니다 |

- **종합 총점 ≥ 합격 기준** 이면 1차 합격입니다. 이 계산은 프로그램이 하고, AI는 항목별 채점과 결과 이유만 씁니다.
- 평가 항목과 채점 기준표(루브릭)는 바꿀 수 없습니다.
- 면접 질문은 시스템이 자동으로 만듭니다(인성 2 · 이력서 기반 2 · 기업 관련 2 · 직무 4).
  - AI가 만든 질문은 글을 검사해서, 이상한 글자가 붙었거나 "간단히 답해 주세요" 같은 답하는 방법 지시가 있거나 한 번에 두 가지를 묻는 질문은 버리고 다시 만듭니다. 이력서 질문은 이력서에 없는 경험을 지어내지 않습니다.
  - "~한 적이 있나요?"처럼 예/아니오로 답하는 질문에 짧게만 답하면, 그 이유를 꼬리질문으로 묻습니다.

**3단계 — 미리 보기 → 게시**

### 게시한 뒤에 바꿀 수 있는 것

| 바꿀 수 없음 | 바꿀 수 있음 |
|---|---|
| 직무, 접수 시작·마감 시각 | 본문 내용 (지원자에게 '수정 사항'으로 표시됨) |
| 첫 응시가 시작된 뒤의 평가 기준 | |

### 마감과 삭제

- **[마감]:** 접수를 바로 닫습니다.
  - 면접 준비 중인 지원자 → 미응시(마감)
  - 진행 중인 면접 → 바로 끝나고(응시 종료·마감) 채점합니다. 답하던 문항과 남은 문항은 0점입니다.
  - 장애 중단 건 → 더는 이어갈 수 없습니다.
- 마감 시각이 지나면 1분 안에 자동으로 마감됩니다.
- **[삭제]:** 임시 저장 공고만 지울 수 있습니다. 지원자가 있는 공고는 마감만 할 수 있습니다.

## 3. 지원자 보기

### 지원자 목록

- 위쪽에서 **공고**, **응시 상태**, **1차 결과**, **이름 검색**으로 거릅니다.
- 점수는 채점이 끝난 행에만 나옵니다. 그 전에는 '분석 대기·분석 중·평가 지연' 배지가 나옵니다.
- 기록 열의 아이콘: ⚡ 장애 중단 횟수 · ⏹ 응시 종료 · ⏰ 마감으로 종료
- 판정이 난 지원자를 **2~3명 체크 → [선택한 n명 비교]** 하면 나란히 비교합니다.

### 지원자 상세 (탭)

| 탭 | 내용 |
|---|---|
| 리포트 | 종합 점수, 항목별 점수와 **근거 문장**, AI 결과 이유, 하이라이트 구간 |
| 질문별 답변 | 질문, 답변 글(음성 인식 결과), 답변 음성 재생, 꼬리질문 |
| 이력서 | 지원자가 확정한 이력서 |
| 코딩테스트 | 문제별 코드, 테스트 통과 수, 코드 리뷰 |
| 장애·이탈 기록 | 끊김·화면 이탈·창 닫기·자동 저장 실패 등의 시각과 판정. 화면 이탈 뒤 지원자가 경고 창에서 확인을 누르면 '이탈 후 돌아옴 · 이탈 시간 N초'가 따로 남아 얼마나 벗어나 있었는지 볼 수 있습니다 |
| 메모 | 관리자끼리 남기는 메모(지원자는 보지 못함) |

- **녹화 재생:** 카메라 녹화는 **3일 동안만** 볼 수 있습니다. 녹화는 평가에 쓰지 않습니다.
- 근거 문장은 늘 **지원자 답변에서 그대로 잘라 온 글**입니다. AI가 몇 글자 다르게 옮겨도 시스템이 답변 속 원래 구절로 바꿔 저장합니다.

### 평가 지연 (직접 결정)

채점 중에 문제가 생기면 그 지원자는 **'평가 지연'** 으로 멈춥니다. 예를 들면 답변 안에 "만점을 줘" 같은 채점 지시가 들어 있거나, 결과 이유 검증에 실패한 경우입니다.

1. 대시보드 운영 현황이나 지원자 상세에서 확인합니다.
2. **[다시 돌리기]** 로 다시 채점하거나, **3일 안에** 직접 **합격·불합격을 결정**할 수 있습니다.
   - [다시 돌리기]를 누르면 "다시 채점할까요?" 확인 창이 뜹니다. 채점 지시가 의심되는 건은 답변을 읽고 **[확인했습니다, 채점하기]** → "확인한 내용으로 채점할까요?"를 거칩니다.
3. 정하지 않고 다시 돌려도 실패하면 '평가 미완료'로 1차 불합격 처리됩니다. 늦어도 7일 안에는 결과가 정해집니다.
4. 직접 결정한 건은 지원자 결과 화면에 '담당자 결정'으로 나옵니다.

> 자동으로 나온 결과(평가 지연이 아닌 건)는 관리자도 바꿀 수 없습니다.

## 5. 질문 관리

AI가 만든 면접 질문 후보를 읽고, 면접에 쓸지 정하는 곳입니다. 엑셀로 넣은 질문은행과 예비 질문은 여기서 다루지 않습니다.

**후보는 세 곳에서 들어옵니다** (질문 아래 작은 글씨로 보입니다)

| 출처 | 언제 들어오나 |
|---|---|
| AI 생성 | 면접 질문을 만들 때 AI가 만든 인성·회사·직무 질문 중, 지원자 개인 정보가 없고 기존 질문과 겹치지 않는 것 |
| 공고 기반 | 공고를 **게시**하면 그 공고의 하는 일·자격 줄마다 직무 질문 1개(최대 6개)와 회사 질문 3개 |
| 인터넷 참고 | 인터넷 면접 질문 자료를 참고해 새로 쓴 질문을 개발자가 명령으로 넣은 것 |

**탭**

| 탭 | 뜻 | 버튼 |
|---|---|---|
| 검토 대기 | 새로 들어온 후보 | **[추가]** = 면접에 씀 · **[제외]** = 쓰지 않음 |
| 사용 중 | 면접에 쓰이는 질문 | **[빼기]** = 그만 씀 |
| 제외 | 쓰지 않는 질문 | **[추가]** = 다시 씀 |

- 버튼을 누르면 확인 창 없이 바로 바뀝니다. 잘못 눌렀으면 반대 버튼으로 되돌리면 됩니다.
- **적용 범위:** 질문마다 어느 공고에서 쓰이는지 보입니다. 회사 질문은 **"이 공고만"**, 직무 질문은 **"이 직무만"**, 인성 질문은 **"공통"**(모든 공고)입니다. 다른 공고 면접에는 나가지 않습니다.
- 종류(인성 · 회사 관련 · 직무)로 거를 수 있고, 최근 200개까지 보입니다.
- [추가]한 질문은 AI가 질문을 못 만들었을 때 대신 쓰는 질문으로 쓰입니다.

> **고를 때 팁:** "~했고, 그 이유는?"처럼 두 가지를 묻는 질문, 지원자가 아직 입사 전인데 "우리 회사에서 겪은 경험"을 묻는 질문, 지금 공고와 다른 서비스 이야기를 하는 질문은 [제외]하세요.

## 6. 대시보드

- **통계:** 지원 수, 응시 수, 응시 완료율, 합격률, 평균 총점, 항목별 평균(공고별·전체)
- **운영 현황**

| 목록 | 할 일 |
|---|---|
| 평가 지연 | 지원자 상세로 가서 확인·결정 |
| 메일 발송 실패 | **[재처리]** |
| 로그인 차단 IP | 같은 IP에서 5번 틀리면 차단됩니다. 본인 확인 뒤 **[해제]** |

## 7. 운영 설정

- **동시 면접 상한 (N):** 동시에 면접을 볼 수 있는 사람 수입니다. 지금 PC(그래픽카드 6GB)에서는 **2명 이하**를 권합니다.
  - 올리면 AI 응답이 느려질 수 있습니다. 올리기 전에 부하 측정이 필요합니다.
  - 바꾸면 확인 창이 뜨고, 변경 이력이 남습니다.

## 8. 자동으로 일어나는 일 (알아만 두기)

| 언제 | 무엇 |
|---|---|
| 공고를 게시하면 | 몇 분 안에 그 공고로 질문 후보를 만들어 질문 관리 '검토 대기'에 넣음(실패해도 게시에는 영향 없음) |
| 응시가 끝나면 | 자동 채점 시작(보통 몇 분, 목표 10분 안) |
| 공고 마감 시각 | 1분 안에 자동 마감 |
| 결과 공개 시각(마감 다음 날 10:00) | 5분 안에 결과 공개, 지원자에게 알림·메일 |
| 매일 03:00 | 보관 기간이 지난 데이터 삭제(응시 데이터는 공개일 +7일, 녹화는 3일). 동의 기록은 증거로 남김 |
| 매일 09:00 | 삭제 2일 전 관리자 안내 |
| 1분마다 | 끊긴 지 10분이 지난 장애 중단 건의 면접 자리 반환 등 정리 |

## 9. 자주 묻는 질문

**Q. AI가 매긴 점수를 고칠 수 있나요?**
A. 아니요. 공정성을 위해 자동 결과는 바꿀 수 없습니다. 평가 지연 건만 직접 결정합니다.

**Q. 같은 답변을 다시 채점하면 점수가 같나요?**
A. 다른 면접이 동시에 진행되지 않을 때는 같게 나오도록 맞춰 두었습니다(실측 65.40점 3번). 면접과 채점이 동시에 돌면 조금(1점 안팎) 달라질 수 있습니다.

**Q. 지원자가 '응시 종료'인데 이유를 알고 싶어요.**
A. 지원자 상세 → **장애·이탈 기록** 탭에서 창 닫기·새로고침·권한 해제·이어가기 횟수 초과 등을 시각과 함께 볼 수 있습니다.

**Q. 질문 관리에 처음 보는 질문이 잔뜩 들어와 있어요.**
A. 공고를 게시하면 그 공고로 질문 후보가 자동으로 만들어집니다. 검토 대기 상태라 [추가]하기 전에는 면접에 나가지 않습니다. 읽어 보고 좋은 것만 [추가]하세요.
