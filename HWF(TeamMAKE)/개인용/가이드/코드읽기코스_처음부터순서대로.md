# 코드 읽기 코스 — 처음부터 순서대로

> 2026-11-11 코드 기준. 줄 번호는 코드가 바뀌면 조금씩 어긋날 수 있어요. 어긋나면 함수 이름으로 찾으세요 (VS Code `Ctrl+P` → 파일 이름, `Ctrl+Shift+O` → 함수 이름).

**이 가이드는 무엇이 다른가요?**

- `코드열람가이드_파일과함수.md` 는 **"이 파일은 누구?"** 를 알려 주는 *인물 소개*예요.
- `프로그램명세서.md` 는 함수 하나하나를 찾아보는 *사전*이에요.
- 이 가이드는 **"어디서 시작해서, 다음엔 어디로 가나?"** 를 알려 주는 *여행 코스*예요. 1번 정류장부터 차례로 따라가면, 마지막엔 프로그램 전체 구조가 머릿속에 그려지게 짰어요.

**읽는 방법**

- 정류장마다 `🧒 쉬운 설명` → `🔧 전문 설명` → `👀 열어 볼 곳` → `📖 코드 한 줄씩 읽기` → `✅ 체크` 순서예요.
- `👀 열어 볼 곳` 의 경로는 모두 `huge/` 폴더 기준이에요. 예: `backend/app/main.py:113` = `huge/backend/app/main.py` 의 113번째 줄.
- 한 정류장의 `✅ 체크` 를 모두 스스로 답할 수 있으면 다음으로 넘어가요. 못 하겠으면 그 파일을 한 번 더 보거나 물어보세요.
- **📖 코드 한 줄씩 읽기** 에는 실제 코드를 옮겨 놓고 한 줄씩 풀어 놨어요. 코드 상자 왼쪽 숫자는 **실제 파일의 줄 번호**이고, 설명의 `줄 5` 도 그 번호예요. VS Code 에서 같은 파일을 옆에 열고 같이 보세요.
- 처음 한 바퀴는 📖 를 건너뛰고 🧒·👀·✅ 만 따라가도 돼요. 큰 그림이 잡힌 뒤 두 번째 바퀴에 📖 를 읽으면 덜 헷갈려요.
- 처음 보는 문법은 정류장 1 앞의 **🧰 문법 상자** 에 있어요.
- 함수 안을 처음부터 끝까지 다 이해하려고 하지 마세요. **함수 이름 → 첫 줄 설명(따옴표 글) → 무엇을 부르는지** 세 가지만 보면 충분해요.

## 🗺 출발 전에 — 큰 그림 한 장

이 프로그램을 **식당**이라고 생각해 봐요.

```
 손님(브라우저)
    │  화면을 보고 버튼을 누름
    ▼
 홀 (frontend, Next.js)  ── "/api/..." 로 주문을 넘김 ──▶  카운터 (api, FastAPI)
                                                              │
                         ┌────────────────────────────────────┼──────────────────────┐
                         ▼                                    ▼                      ▼
                   창고 (postgres·objectstore)       뒷주방 (worker, Celery)    전문 요리사 (AI 컨테이너)
                   손님 정보·공고·답변 보관          시간 오래 걸리는 채점·메일    LLM·STT·TTS·임베딩·OCR
```

| 비유 | 실제 | 폴더 |
|---|---|---|
| 홀 | 화면 (Next.js 16, React) | `frontend/` |
| 카운터 | API 서버 (FastAPI) | `backend/app/main.py`, `backend/app/routers/` |
| 주방 | 실제 일을 하는 함수들 | `backend/app/services/`, `backend/app/interview/` |
| 규칙판 | 정해진 규칙(상태, 점수 계산) | `backend/app/domain/` |
| 뒷주방 | 오래 걸리는 일, 정해진 시각에 하는 일 | `backend/app/worker.py`, `backend/app/jobs.py` |
| 창고 | DB·파일 저장소·Redis | `compose.infra.yml` |
| 전문 요리사 | AI 서버들 | `ai/`, `compose.ai.yml` |

🔧 **전문 설명:** 브라우저는 Next.js 서버(8080)에만 접속하고, Next.js 가 `/api/*` 를 FastAPI(8000)로 넘겨요(rewrite). 그래서 쿠키와 WebSocket 이 같은 출처에서 동작해요. 무거운 작업(채점, 메일, 코드 실행)은 Celery 워커가 Redis 큐에서 꺼내 처리해요.

처음엔 훑어만 보세요. 코스를 가다가 처음 보는 모양이 나오면 여기로 돌아와 찾아보면 돼요.

| `-> dict` | "이 자판기는 사전(dict)을 내놓아요" | 반환 타입 힌트 |
| `str \| None` | 글자이거나, 아무것도 없거나 | Union 타입. `None` = 값 없음 |
| `class 이름:` | 붕어빵 틀 | 클래스 정의 |
| `self` | 틀로 찍어 낸 "나 자신" 붕어빵 | 인스턴스 자기 자신 |
| `@무언가` (함수 위) | 자판기에 스티커 붙이기. "이 자판기는 /login 주소 담당" 처럼 | 데코레이터. 함수를 감싸 기능을 덧붙임 |
| `async def` / `await` | "기다리는 동안 다른 손님도 받을 수 있는 자판기" / "여기서 잠깐 기다려요" | 비동기 함수 / 결과가 올 때까지 양보하며 대기 |
| `with A as b:` | 빌려 쓰고 끝나면 자동으로 반납 | 컨텍스트 매니저. 끝날 때 정리 코드가 자동 실행 |
| `try: … except X: … finally: …` | 해 보고, X 문제가 생기면 이렇게, 마지막엔 무조건 이것 | 예외 처리 |
| `raise 오류` | "문제 생겼어요!" 하고 손 들기 | 예외 발생. 위쪽 누군가가 받아 처리 |
| `yield` | "여기서 잠깐 넘겨줄게, 다 쓰면 다시 와" | 제너레이터. FastAPI 에선 "빌려주고, 끝나면 정리" 용도 |
| `A or B` | A 가 비어 있으면 B | 앞이 거짓 같은 값이면 뒤를 씀 |
| `x if 조건 else y` | 조건이 맞으면 x, 아니면 y | 조건 표현식 |
| `[x for x in 목록 if 조건]` | 목록에서 조건 맞는 것만 골라 새 목록 | 리스트 컴프리헨션 |

## 정류장 1. 전원 켜기 — 무엇이 떠 있나

🧒 **쉬운 설명:** 식당 문을 열려면 창고, 요리사, 카운터를 순서대로 출근시켜야 해요. `up.sh` 가 "창고 → 요리사 → 카운터·홀" 순서로 출근 도장을 찍어 주는 출근부예요.

🔧 **전문 설명:** Docker Compose 파일이 세 묶음으로 나뉘어 있고, `up.sh` 가 공유 네트워크(`huge-front`, `huge-internal`)를 만든 뒤 `infra → ai → app` 순으로 `docker compose up -d --build` 해요. `huge-internal` 은 `--internal` 이라 바깥 인터넷으로 못 나가요.

👀 **열어 볼 곳**

1. `scripts/up.sh` — 9줄짜리. 전체를 읽어요.
2. `compose.infra.yml` — 창고: `postgres`(DB), `redis`(빠른 메모장·작업 줄), `objectstore`(파일 보관, RustFS), `mailpit`(가짜 우체국)
3. `compose.ai.yml` — 요리사: `llm-rt`(면접 중 빠른 LLM 4B), `llm-eval`(채점용 8B), `stt`(말→글), `tts`(글→말), `embed`(글→숫자 벡터), `ocr`(사진 속 글자 읽기)
4. `compose.app.yml` — 카운터와 일꾼: `api`, `worker-eval`, `worker`, `worker-sandbox`, `scheduler`, `frontend`
5. `README.md` — 켜는 법과 주소

### 📖 코드 한 줄씩 읽기 — `scripts/up.sh` (9줄 전부)

```sh
1  #!/usr/bin/env sh
2  # 공유 네트워크를 만들고 infra → ai → app 순서로 띄운다.  사용: sh scripts/up.sh [infra|ai|app]
3  set -e
4  cd "$(dirname "$0")/.."
5  docker network inspect huge-front >/dev/null 2>&1 || docker network create huge-front
6  docker network inspect huge-internal >/dev/null 2>&1 || docker network create --internal huge-internal
7  for part in ${1:-infra ai app}; do
8    MSYS_NO_PATHCONV=1 docker compose -f "compose.$part.yml" up -d --build
9  done
```

- **줄 1** `#!/usr/bin/env sh` — 🧒 "이 쪽지는 sh 라는 사람이 읽어요" 라는 표시. 🔧 셔뱅(shebang). 실행할 해석기를 지정해요.
- **줄 2** `#` 로 시작하면 주석. 컴퓨터는 무시하고 사람만 읽어요. 사용법이 적혀 있어요.
- **줄 3** `set -e` — 🧒 "한 줄이라도 실패하면 바로 멈춰!" 창고가 안 열렸는데 카운터를 여는 일을 막아요. 🔧 명령이 0 이 아닌 종료 코드를 내면 스크립트를 즉시 끝내요.
- **줄 4** `cd "$(dirname "$0")/.."` — 안쪽부터 풀어요.
  - `$0` = 지금 실행 중인 이 파일 경로 → `scripts/up.sh`
  - `dirname …` = 그 파일이 든 폴더 → `scripts`
  - `/..` = 한 칸 위 폴더 → `huge`
  - `$( … )` = 안의 명령을 실행한 **결과 글자**로 바꿔 끼움
  - 🧒 어느 폴더에서 이 쪽지를 실행하든 **항상 `huge` 폴더로 먼저 이동**해요. 그래야 다음 줄의 `compose.infra.yml` 을 찾을 수 있어요.
  - 🔧 큰따옴표는 경로에 공백·괄호(`HWF(TeamMAKE)`)가 있어도 한 덩어리로 다루게 해요.
- **줄 5** — 두 부분이 `||` 로 이어져 있어요.
  - `docker network inspect huge-front` = "huge-front 라는 길(네트워크)이 있나 확인"
  - `>/dev/null 2>&1` = 🧒 확인 결과 글자를 화면에 안 띄우고 쓰레기통에 버림. 🔧 표준 출력을 `/dev/null` 로, 표준 오류(2)도 표준 출력(1)과 같은 곳으로 보내요.
  - `||` = "왼쪽이 **실패하면** 오른쪽을 해라". 길이 없으면(확인 실패) → `docker network create huge-front` 로 만들어요.
  - 🧒 "길이 있으면 그냥 지나가고, 없으면 만든다." 두 번 실행해도 안전해요.
  - 🔧 `||` 로 이어진 왼쪽 명령의 실패는 `set -e` 가 멈추지 않아요.
- **줄 6** — 줄 5 와 같은데 `--internal` 이 붙었어요. 🧒 **바깥 인터넷으로 나가는 문이 없는 비밀 복도**예요. DB 와 AI 서버는 이 복도에만 있어서 밖에서 직접 들어올 수 없어요. 🔧 internal 네트워크는 외부 라우팅이 막혀요. 지원자 정보가 밖으로 새지 않게 하는 설계예요.
- **줄 7** `for part in ${1:-infra ai app}; do`
  - `$1` = 이 쪽지를 실행할 때 덧붙인 첫 번째 말. `sh scripts/up.sh app` 이면 `$1` 은 `app`.
  - `${1:-infra ai app}` = "`$1` 이 비어 있으면 `infra ai app` 을 대신 써라"
  - `for part in … ; do … done` = 공백으로 나눈 낱말마다 한 번씩 반복. `part` 에 `infra` → `ai` → `app` 이 차례로 들어가요.
- **줄 8** — 반복할 때마다 하는 일.
  - `MSYS_NO_PATHCONV=1` = 🔧 Windows Git Bash 가 `/data` 같은 경로를 `C:/...` 로 멋대로 바꾸는 걸 막아요. 이 명령 하나에만 적용돼요.
  - `docker compose -f "compose.$part.yml"` = `part` 가 `infra` 면 `compose.infra.yml` 파일을 써요.
  - `up` = 띄우기, `-d` = 뒤에서 조용히 실행(창을 붙잡지 않음), `--build` = 코드가 바뀌었으면 이미지를 새로 만들기.
- **줄 9** `done` = 반복 끝.

**🧪 써 보기**

| 명령 | 결과 |
|---|---|
| `sh scripts/up.sh` | 셋 다 순서대로 |
| `sh scripts/up.sh app` | 카운터·홀만 (코드 고친 뒤 자주 씀) |
| `sh scripts/up.sh "ai app"` | 요리사와 카운터만 (따옴표로 묶어야 한 덩어리) |

## 정류장 2. 백엔드 출발점 — `main.py`

#### `backend/app/main.py:68` — `lifespan` (개점 준비)

```python
68  @asynccontextmanager
69  async def lifespan(_app: FastAPI):
70      Base.metadata.create_all(engine)
71      migrate.addColumns(engine)
72      with SessionLocal() as db:
73          seedJobCodes(db)
74      await asyncio.to_thread(storage.ensureBucket)
```

- **줄 68** `@asynccontextmanager` — 🧒 "이 함수는 **앞부분(문 열기)** 과 **뒷부분(문 닫기)** 이 있어요" 스티커. 🔧 `yield` 앞은 시작 시, 뒤는 종료 시 실행돼요.
- **줄 69** `_app` 앞의 `_` 는 "받긴 하지만 안 써요" 라는 표시예요.
- **줄 70** `Base.metadata.create_all(engine)` — 🧒 `models.py` 의 서랍 목록표를 보고 **창고에 없는 서랍을 만들어요**. 이미 있으면 그냥 둬요. 🔧 `CREATE TABLE IF NOT EXISTS`. 단, 이미 있는 테이블에 칸을 추가하지는 않아요.
- **줄 71** `migrate.addColumns(engine)` — 그래서 이게 필요해요. 🧒 **이미 있는 서랍에 새로 생긴 칸을 붙여요**. 🔧 `ALTER TABLE … ADD COLUMN` 을 직접 실행하는 간단한 마이그레이션이에요.
- **줄 72~73** `with SessionLocal() as db:` — DB 대화 창구를 하나 빌려서(`db`), `seedJobCodes` 로 **직무 코드 같은 기본 데이터**를 넣고, `with` 가 끝나면 창구를 자동으로 반납해요.
- **줄 74** `await asyncio.to_thread(storage.ensureBucket)` — 🧒 파일 보관함(버킷)이 있는지 확인하고 없으면 만들어요. 이 일은 "기다리는 동안 아무것도 못 하는" 방식이라, **다른 일꾼(스레드)에게 시켜서** 카운터가 멈추지 않게 해요. 🔧 동기 블로킹 함수를 스레드 풀에서 실행해 이벤트 루프를 막지 않아요.
- **줄 75** `recoverAfterRestart()` — 서버가 꺼지기 직전에 하다 만 일을 정리해요 (아래 상자).
- **줄 76** `checkpoint.openSaver()` — 면접 진행표의 **책갈피 보관함**(LangGraph 체크포인트, Postgres)에 연결해요.
- **줄 77~78** `spawn(...)` — 🧒 "이 일은 **기다리지 말고 따로 시작해 둬**". LLM 깨우기(`warmUp`)와 1분마다 도는 정리 일(`runForever`)을 따로 출발시켜요. 🔧 `spawn` (62줄)은 `create_task` 로 태스크를 만들고 `backgroundTasks` 집합에 넣어 가비지 컬렉션으로 사라지지 않게 해요.
- **줄 79** `yield` — 🧒 **여기서 문이 열려요.** 서버가 손님(요청)을 받는 동안 이 줄에서 멈춰 있어요.
- **줄 80~82** 서버를 끌 때 실행. 따로 돌던 일을 멈추고(`cancel`), 책갈피 보관함 연결을 닫아요.

#### `backend/app/db.py` (28줄 전부)

```python
13  def makeEngine(url: str):
14      if url.startswith("sqlite"):
15          return create_engine(url, connect_args={"check_same_thread": False})
16      return create_engine(url, pool_pre_ping=True, pool_size=10, max_overflow=10)
19  engine = makeEngine(ENV.databaseUrl)
20  SessionLocal = sessionmaker(bind=engine, expire_on_commit=False)
23  def getDb() -> Iterator[Session]:
24      db = SessionLocal()
25      try:
26          yield db
27      finally:
28          db.close()
```

- **makeEngine** — 🧒 창고로 가는 **전화선 묶음**을 만들어요.
  - 주소가 `sqlite` 로 시작하면 → 테스트용 작은 파일 DB. `check_same_thread: False` 는 여러 일꾼이 같이 쓰게 허락하는 설정.
  - 아니면 → 진짜 Postgres. `pool_size=10` = 전화선 10개를 미리 깔아 둠, `max_overflow=10` = 바쁠 땐 10개 더, `pool_pre_ping=True` = 쓰기 전에 "여보세요?" 확인해서 끊긴 선을 안 씀.
- **engine** — 서버 전체가 함께 쓰는 전화선 묶음 하나.
- **SessionLocal** — 🧒 **대화 창구를 찍어 내는 틀**. `SessionLocal()` 하면 창구 하나가 생겨요. 🔧 `expire_on_commit=False` 는 커밋 뒤에도 객체 값을 다시 읽지 않고 그대로 쓰게 해요.
- **getDb** — 요청 하나마다:
  1. 창구 하나 열고 (`SessionLocal()`)
  2. `yield db` 로 **창구 함수에 빌려줘요**
  3. 창구 함수가 끝나면 → `finally` 에서 **무조건 닫아요** (오류가 났어도)
  - 🔧 라우터에서 `db: Session = Depends(getDb)` 라고 쓰면 FastAPI 가 이 흐름을 자동으로 해 줘요.

## 정류장 4. 첫 요청 따라가기 — 로그인 한 바퀴

이제 처음으로 **화면 → 서버 → DB → 화면** 을 한 바퀴 돌아요. 이 바퀴를 한 번 이해하면 다른 기능은 다 같은 모양의 반복이에요.

🧒 **쉬운 설명:** 손님이 "저 철수예요, 비밀번호는 ○○" 라고 말하면 → 홀 직원이 쪽지에 적어 카운터로 → 카운터가 장부와 비교 → 맞으면 **입장 팔찌(쿠키)** 를 채워 줌 → 다음부터는 팔찌만 보여 주면 돼요.

🔧 **전문 설명:** 로그인 성공 시 무작위 토큰을 만들어 해시만 DB(`login_sessions`)에 저장하고, 원본 토큰은 `httponly` 쿠키로 보내요. 이후 요청은 `Depends(currentUser)` 가 쿠키 → 해시 → 세션 행 → 사용자로 바꿔 줘요. 비밀번호는 해시로만 비교해요.

## 정류장 7. 면접 진행 — 프로그램의 심장 ❤️

가장 길고 어려운 정류장이에요. 천천히, 두세 번에 나눠 보세요.

🧒 **쉬운 설명:** 면접은 **전화 통화**와 같아요. 보통 요청은 "편지 한 장 보내고 답장 한 장" 이지만, 면접은 서로 계속 말을 주고받아야 하니 **전화선(WebSocket)** 을 연결해 둬요. 서버 쪽에서는 `LiveSession` 이라는 면접관이 전화를 받고, **면접 진행표(LangGraph 그래프)** 를 보며 "질문 → 답 기다리기 → 받아쓰기 → 꼬리질문 할까? → 다음 질문" 을 반복해요. 진행표에는 책갈피(체크포인트)가 있어서 전화가 끊겨도 그 자리부터 이어 갈 수 있어요.

🔧 **전문 설명:** `interview/start` 가 세션 행을 만들고 `ws_url` 을 돌려줘요. 브라우저는 마이크 소리를 16kHz PCM 조각으로 WebSocket 에 보내고, 서버는 JSON 메시지(`question`, `caption`, `warn`, `phase`, `terminate` …)로 답해요. `LiveSession.runInterview` 가 그래프를 `ainvoke` 하다가 `wait` 노드의 `interrupt` 에서 멈추면 `collectAnswer` 로 답을 받고 `Command(resume=...)` 로 재개해요. 체크포인트는 `AsyncPostgresSaver`, thread_id 는 지원 번호예요.

## 정류장 9. 채점과 결과 — 뒷주방의 일

🧒 **쉬운 설명:** 채점은 오래 걸려요(1~3분). 손님을 세워 두지 않으려고 **주문표를 뒷주방에 넘기고(큐)**, 뒷주방 요리사(worker)가 천천히 채점해요. AI 는 "항목별로 몇 점인지와 그 근거 문장" 만 매기고, **합격·불합격은 AI 가 아니라 계산 규칙(총점 ≥ 기준점)** 이 정해요.

🔧 **전문 설명:** `lifecycle.finish` → `queueEvaluation` → `worker.enqueueEvaluation` 으로 Celery 작업이 들어가요. `evaluateTask` 가 Redis 잠금을 잡고 `evaluation.evaluate` 를 실행. 문항별 루브릭 채점(T5, `scoreQuestion`) → `computeScores`(domain/scoring.py 의 가중치·반올림) → 합불 결정 → 사유(T10)·요약(T6)·피드백 → `save`. - 켜져 있고 코딩 비율 30%, 코딩 점수 50 이라면 → 줄 79:
  `77.50 × 70% + 50 × 30% = 54.25 + 15.00 =` **69.25**

**4단계 — 합불:** 총점이 공고의 **기준점 이상이면 합격**. 🧒 AI 는 1단계의 0~5점과 근거만 주고, **합격·불합격은 이 계산기가 정해요.**

🔧 `Decimal` 은 `0.1 + 0.2 = 0.30000000000000004` 같은 소수 오차가 없는 숫자예요. 점수에 꼭 필요해요. `roundScore` 는 소수 둘째 자리 반올림(`ROUND_HALF_UP`, 우리가 아는 사사오입).

✅ **체크**

- [ ] "AI 가 점수를 매기지만 합불은 코드가 정한다" 를 `evaluate` 안에서 찾아 확인했다
- [ ] 채점을 api 가 아닌 worker 가 하는 이유를 말할 수 있다
- [ ] 🧪 직접 해 보기: `backend/tests/test_scoring.py` 를 읽고 돌려 본다. 가중치를 바꾸면 총점이 어떻게 변하는지 테스트에서 찾는다

## 정류장 11. 뒤에서 혼자 도는 일 — 시계 보는 일꾼

🧒 **쉬운 설명:** 손님이 아무것도 안 해도 식당은 돌아가요. "마감 시간 된 공고 닫기", "5분마다 빠진 채점 다시 넣기", "새벽 3시에 오래된 자료 버리기", "결과 공개 시각에 알림 보내기" 같은 일을 **시계를 보고** 해요.

👀 **열어 볼 곳**

1. `backend/app/jobs.py:70` — `runForever` 반복문 (15줄)
2. `backend/app/worker.py:66` — `beat_schedule` 표. 이름과 시간만 보면 돼요
3. `backend/app/worker.py:304` — `sweepTask` (빠진 채점·결과 공개 처리)
4. `backend/app/services/retention.py` — 보관 기간이 지난 자료 삭제. 개인정보 원칙(CLAUDE.md 4.3)과 연결
5. `backend/app/services/notify.py` — 알림·메일

### 📖 코드 한 줄씩 읽기 — `jobs.py:70`

```python
70  async def runForever() -> None:
71      while True:
72          db = SessionLocal()
73          try:
74              sweepOrphans(db)
75              releaseHeldSeats(db)
76              await closeExpiredPostings(db)
77              admission.reconcile(db)
78              regradePending()
79          except Exception:
80              log.exception("periodic job failed")
81              db.rollback()
82          finally:
83              db.close()
84          await asyncio.sleep(INTERVAL_SEC)
```

- **줄 71** `while True` — 🧒 **영원히 반복** (서버가 꺼질 때 `cancel` 될 때까지).
- **줄 74** 연결이 끊긴 채 방치된 면접 정리
- **줄 75** 장애로 붙잡아 둔 면접 자리(10분)가 지나면 반납
- **줄 76** 마감 시각이 지난 공고 닫기 (그 공고의 진행 중 응시도 마감 처리)
- **줄 77** 동시 면접 자리 수 맞추기
- **줄 78** 확인 필요 건 다시 채점 맡기기
- **줄 79~81** 🧒 하나가 실패해도 **반복은 멈추지 않아요.** 기록만 남기고 고친 것은 되돌려요(`rollback`).
- **줄 84** `INTERVAL_SEC = 60` → **1분 쉬고** 다시. 🔧 `asyncio.sleep` 은 쉬는 동안 다른 요청을 막지 않아요 (`time.sleep` 과 달라요).

### 📖 코드 한 줄씩 읽기 — 오류 쪽지 한 모양: `errors.py` (31줄 전부)

```python
 8  class ApiError(Exception):
 9      def __init__(self, status: int, code: str, message: str):
10          self.status = status
11          self.code = code
12          self.message = message

15  def notFound() -> ApiError:
16      return ApiError(404, "NOT_FOUND", "찾을 수 없습니다.")

19  async def apiErrorHandler(_request: Request, exc: ApiError):
20      return JSONResponse(status_code=exc.status, content={"code": exc.code, "message": exc.message})

23  async def unexpectedErrorHandler(_request: Request, _exc: Exception):
25      return JSONResponse(status_code=500, content={"code": "SERVER_ERROR", "message": "잠시 후 다시 시도해 주세요."})

28  async def validationErrorHandler(_request: Request, exc: RequestValidationError):
29      first = exc.errors()[0] if exc.errors() else {}
30      field = ".".join(str(p) for p in first.get("loc", [])[1:])
31      return JSONResponse(status_code=422, content={"code": "VALIDATION_ERROR", "message": f"{field}: {first.get('msg', '형식 오류')}"})
```

- **줄 8~12** 🧒 우리만의 **"문제 쪽지" 틀**. 쪽지에는 번호(`status`, 예: 409), 짧은 이름(`code`, 예: `ALREADY_APPLIED`), 사람이 읽을 문장(`message`) 세 칸이 있어요. 🔧 `Exception` 을 상속해서 `raise` 할 수 있어요.
- **줄 15~16** 404 쪽지를 자주 써서 만들어 둔 바로가기.
- **줄 19~20** 창구 어디서든 `raise ApiError(...)` 하면 → 이 함수가 받아서 `{"code": …, "message": …}` 답장으로 바꿔요. 화면의 `api.ts` 줄 39 가 이 두 칸을 읽어요. 🧒 **서버와 화면이 같은 쪽지 모양을 약속**한 거예요.
- **줄 23~25** 예상 못 한 오류(버그)는 🧒 **"잠시 후 다시" 만 말하고 속사정은 숨겨요.** 오류 속에 코드 위치나 데이터가 보이면 나쁜 사람에게 힌트가 되니까요. 진짜 원인은 서버 로그에만 남아요.
- **줄 28~31** 보낸 모양이 틀렸을 때(예: 이메일 칸이 없음) → 어느 칸이 왜 틀렸는지 한 줄로.
  - 🔧 `loc` 은 `["body", "email"]` 같은 위치 목록. `[1:]` 로 앞의 `body` 를 빼고 `"email"` 만 남겨요.
