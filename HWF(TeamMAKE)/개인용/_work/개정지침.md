모든 작성·검토 에이전트가 같은 기준으로 일하기 위한 공통 지침이다.

## 1. 목적

`huge/CONFLICTS.md`(구현과 설계의 차이 기록)를 바탕으로, 프로젝트 설계 문서 전체를 **실제 구현(`huge/`)에 맞춘 개인용 개정본**으로 만든다.
팀 원본 파일(`HWF(TeamMAKE)/` 바로 아래 파일, `HWF(TRDPRD)/팀용/`)은 절대 수정하지 않는다. 결과물은 모두 `HWF(TeamMAKE)/개인용/` 에 둔다.

## 3. 개정 규칙

1. **기준:** 구현이 사실의 기준이다. `huge/CONFLICTS.md` 항목과 실제 코드(`huge/backend/app`, `huge/frontend`)를 확인해 문서를 구현에 맞춘다. CONFLICTS 의 설명이 코드와 다르면 코드를 확인하고, 그 차이는 논의사항으로 보고한다.
2. **해결·승인된 항목**(CONFLICTS 에 '해결', '사용자 결정', '사용자 확인', '승인됨', '이대로' 등): 본문을 구현대로 고친다.
3. **아직 확인 필요·결정 필요인 항목**(C1, C11, B1 ①②, D3, F5, F6, V2~V4, S5, OCR 10쪽 상한, U7 등 '확인 필요'·'결정 필요'·'요청 필요' 표시): 본문은 현재 구현대로 적되 문장 끝에 `〔미확정: CONFLICTS <ID>〕` 표시를 붙이고, 문서 끝 '논의사항' 절에도 모은다.
4. **미구현 기능**(공고 불러오기 V2, 관리자 원본 이력서 보기 V3, 자동 보호 admission_guard F6, 하루 메일 상한 S5, 이메일 인증 등): 요구사항을 지우지 않는다. '현재 구현 범위 밖(미구현)'으로 표시하고 이후 범위로 옮긴다.
5. **CONFLICTS ID 를 근거로 남긴다.** 바뀐 곳마다 개정 이력에 ID(A1, B1, U5, T20 …)를 적는다. 본문에는 꼭 필요할 때만 짧게 적는다.
6. **적지 말 것:** AI 가 만든 질문을 질문 DB 에 `pending` 으로 쌓고 관리자 '질문 관리'(`/admin/questions`)에서 추가하는 기능은 사용자 요청으로 **어떤 문서에도 적지 않는다.** (CONFLICTS 의 'generated 로 다시 넣기 … 미구현' 문장도 옮겨 적지 않는다.) `.env` 파일은 읽지 않는다.
7. **문체:** 원본 문서의 문체·용어·표 형식을 그대로 따른다(쉬운 한국어, 짧은 문장). 원본에 없는 장을 새로 만들지 않는다. 단 문서 끝 '논의사항' 절과 개정 이력 행은 추가한다.
8. **머리말:** 문서 맨 앞 버전·작성일을 새 버전·2026-11-03 으로 바꾸고, "개인용 개정본 — 팀 원본 아님, 기준: 구현(`huge/`) + `huge/CONFLICTS.md` (2026-11-03)" 문구를 넣는다. 개정 이력 표에 새 버전 행을 넣는다.
9. **교차 참조:** 다른 문서를 가리키는 버전은 2장 표의 새 버전으로 바꾼다(예: "TRD v1.5" → "TRD v1.6"). 단 이력·과거 결정을 설명하는 문장의 옛 버전은 그대로 둔다.
10. **문서 간 충돌 해소:** CONFLICTS A1·A2 처럼 문서끼리 다른 것은 구현 쪽으로 통일한다(A1: STT 실패 → 같은 질문 재답변이 아니라 장애 중단. 재시도 횟수는 코드대로 `stt_retry_limit`=2(최대 3번 시도) — CONFLICTS A1 의 '1회'는 코드와 다름 / A2: `next` 는 화면 경로만).

## 5. 주요 구현 사실 요약 (빠른 참고, 자세한 것은 CONFLICTS)

- 합불: 코드가 `총점 ≥ 합격 기준`으로 정함. LLM(T10, CPU Qwen3 8B)은 이유만 씀(S1). 채점은 응시 끝난 뒤 한 번에(S2).
- 면접 흐름: LangGraph 그래프 + PostgreSQL 체크포인트(thread_id=지원 id). 질문 구성 그래프는 api 안, 체크포인트 없음(B1). 이어가기는 원장(applications) 기준 `locate`.
- 작업 큐: Celery(worker·worker-eval·worker-sandbox·scheduler)(B2). 코드 실행은 worker-sandbox 만 docker.sock(B4).
- 저장소 RustFS + 앱 AES-GCM(B5). 답변 음성은 WebSocket 이진 16kHz PCM, WebRTC 없음(V4).
- 회사명 표기 안 함(U1), '회사 소개'→'부서 소개'(V1), AI 공고 초안 1단계(U2), 맡을 일 선택(U6), 이력서 OCR 1단계(U4), 질문 RAG 우선→질문은행→예비(U5), 꼬리질문 목표 시간 `followup_target_sec`(U7), '면접 준비 중'·[이력서 제출](U3).
- 이어가기 3회(D1, `resume_limit`), 동시 면접 상한 1~20(D2), 브라우저 Chrome·Edge 120+(C5), 미연결 90초 장애(C11).
- 녹화: 카메라+소리, 조각별 객체, Range 없음, 매시 30분 삭제(R1~R6). 비밀번호 찾기 1분 1통(P1·P2). 철회·탈퇴(W1~W5). 감사 로그 점 표기(M1).
- 통계 `stats_archive`(F1), 설정 기록은 감사 로그(F8), 질문은행 거르기 excluded(F4-2), 판정 없는 건 삭제일(F9).
- 테이블 실제 구조 차이 T1~T38 ('정의서 수정 요청' 항목은 개인용 테이블 정의서에서 실제 구조로 고친다).
