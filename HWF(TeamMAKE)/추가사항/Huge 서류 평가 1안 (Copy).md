# Huge 서류 평가 1안

면접 전에 AI가 이력서와 선택 서류(자소서, 포트폴리오)를 항목별 수준 기준표로 평가해 사람 없이 서류 합격과 불합격을 정합니다. AI는 단계와 근거 문장만 고르고, 점수와 합격 여부는 코드가 계산합니다. 합격선 근처의 지원자는 더 큰 AI 모델이 한 번 더 평가합니다. 기존 면접 채점(4B가 점수, 8B가 한 번 더)과 같은 방식입니다.

흐름

## 이력서 제출부터 서류 결과까지

정상 흐름 AI가 하는 단계 근거가 없을 때 다시 시키기 *1**2*평가 차수 (최대 두 번)

합격선 75점, 재평가 구간 5점이면 1차 점수 80점 이상은 자동 합격, 70점 미만은 자동 불합격, 그 사이는 2차 평가로 갑니다. 2차 점수가 75점 이상이면 합격, 미만이면 불합격입니다. 관리자는 판정에 끼지 않고, 끝난 결과의 점수와 근거를 볼 수 있습니다.

평가 두 번

## 1차 평가와 2차 평가

모든 지원자는 1차 평가를 한 번 받습니다. 1차 점수가 합격선 근처(± 재평가 구간)인 지원자만 더 큰 모델로 2차 평가를 받습니다. 2차는 1차 결과를 보지 않고 처음부터 다시 평가하며, 최종 판정은 2차 점수로만 합니다.

| 구분 | *1*1차 평가 | 2차 평가 |
| --- | --- | --- |
| **대상** | 모든 지원자 | 1차 점수가 합격선 ± 재평가 구간 안인 지원자만 |
| **AI 모델** | Qwen3-4B. 지금 Huge의 `llm-rt` 컨테이너, GPU에서 돔. 면접 질문과 꼬리질문을 만드는 모델 | Qwen3-8B. 지금 Huge의 `llm-eval` 컨테이너, CPU에서 돔. 면접 결과의 이유를 쓰는 모델 |
| **넣는 것** | 같음: 단계 기준표, 공고의 필수·우대 기술, 그 항목에 해당하는 서류 부분 (이력서 · 자소서 · 포트폴리오) |  |
| **근거 확인** | 같음: 근거 문장이 제출 서류에 없으면 1번 다시, 그래도 없으면 0단계 |  |
| **결과의 쓰임** | 자동 합격 · 자동 불합격 · 2차로 보낼지 정함 | 이 점수로 최종 합격 · 불합격. 1차 점수는 기록으로만 남김 |
| **걸리는 시간** | 짧음 (GPU) | 김 (CPU, 실측 필요) |

제출 서류

## 이력서 · 자소서 · 포트폴리오

자소서와 포트폴리오는 선택입니다. 따로 점수 항목을 만들지 않고, 6개 항목의 근거를 찾는 곳으로만 씁니다. 내지 않았다고 감점하지 않지만, 내면 근거가 늘어 높은 단계를 받을 수 있습니다.

| 서류 | 필수 | 받는 방법 | 지금 Huge |
| --- | --- | --- | --- |
| **이력서** | 필수 | 파일 올리기 또는 직접 작성 | 있음 |
| **자소서** | 선택 | 직접 작성 (5,000자까지) 또는 이력서 파일에 함께 | 있음. 이력서의 `cover_letter` 칸 |
| **포트폴리오** | 선택 | PDF 올리기. 서버가 글자를 뽑아 평가에 씀 | 없음. 새로 만들어야 함 |

| 평가 항목 | 근거를 찾는 곳 |
| --- | --- |
| 프로젝트 | 이력서 프로젝트 칸 · 포트폴리오 |
| 기술스택 | 이력서 기술 칸 · 프로젝트의 사용 기술 · 포트폴리오 |
| 경력 | 이력서 경력 칸 |
| 경험 | 자소서 · 포트폴리오 |
| 자격증 | 이력서 자격증 칸 |
| 학력 | 이력서 학력 칸 (전공만, 학교 이름 제외) |

## 항목별 수준 기준표와 점수 계산

칸을 누르면 그 단계로 바뀌고 점수가 다시 계산됩니다. 처음 상태는 예시 지원자(신입 AI/AX 엔지니어 공고, 필수 기술 Python·SQL·PyTorch)입니다. 항목 점수 = 단계 ÷ 그 항목의 최고 단계 × 배점입니다.

AI 한 번 호출의 예

## 프로젝트 항목을 평가할 때

항목마다 LLM을 따로 부릅니다. 이름과 학교 이름은 넣지 않고, 그 항목에 해당하는 이력서 부분만 넣습니다.

### AI에 넣는 것

```
[항목] 프로젝트 (배점 12)
[단계 기준]
0 없음
1 직무와 무관하거나 본인 역할이 불분명
2 직무 관련, 본인 역할 명시
3 직무 관련 + 역할 + 결과(수치·배포)
[공고] 신입 AI/AX 엔지니어
필수: Python, SQL, PyTorch
[이력서 · 프로젝트 칸]
사내 문서 RAG 챗봇 (2025.03~06)
검색 모듈 담당, LangChain으로 구현
[포트폴리오 · 제출한 경우만]
RAG 챗봇 화면 설명, 구조도 설명 글
```

### AI가 내는 것

```
{
  "item": "프로젝트",
  "level": 2,
  "evidence": "검색 모듈 담당, LangChain으로 구현",
  "reason": "직무 관련, 역할 명시, 결과 수치 없음"
}
```

### 코드가 확인하는 것

근거 있음 AI가 고른 문장이 이력서 · 자소서 · 포트폴리오 중 한 곳에 그대로 있음 → 2단계 인정 → 12 × 2/3 = 8.0점

근거 없음 AI가 고른 문장이 어느 서류에도 없음 → 1번 다시 → 또 없으면 0단계

## Huge에서 바꿀 곳과 정할 것

### 바꿀 곳

1. 질문 생성 시작을 서류 합격 뒤로 옮김 (`routers/applications.py:227`)
2. 지원 상태 3개 추가: 서류 평가 중 · 서류 2차 평가 중 · 서류 불합격 (`domain/status.py`)
3. 공고 칸 추가: 서류 평가 사용 여부 · 필수 기술 · 우대 기술 · 합격선
4. 평가 서비스 파일 (4B 1차 평가 + 경계 지원자만 8B 재평가)과 항목별 결과 테이블 (1차 · 재평가의 단계 · 근거 · 점수)
5. 화면: 지원 시 포트폴리오 PDF 올리기(새로), 관리자 결과 열람과 근거, 지원자 서류 결과와 이의 신청 버튼

### 정할 것

1. 결과를 제출 직후 보여 줄지, 나중에 알림으로 보낼지 (재평가 대상은 8B가 CPU에서 돌아 더 늦음)
2. 근거가 없을 때 0단계로 할지 (면접 채점 T5는 1점)
3. 재평가 구간 폭 (0이면 재평가 없음)

### 사람 없이 판정하므로 넣을 것

- 불합격자에게 항목별 단계와 근거 공개 (자동화된 결정에 대한 설명 요구권, 개인정보보호법 제37조의2)
- 이의 신청이 들어오면 관리자가 다시 보는 경로

### 지금 없는 것

- "경험" 칸: 이력서 형식에 없음. 자소서와 포트폴리오에서 근거를 찾음
- 포트폴리오: 올리는 칸과 저장 방식이 없음. PDF만 받고 글자를 뽑아 씀 (링크는 내용을 가져오지 않음)
- 학교 이름은 평가에서 제외하고 전공 관련성만 봄

제안 자료입니다. Huge 코드에는 아직 서류 평가 기능이 없습니다. 배점(40점), 기본 점수(60점), 합격선(75점), 예시 지원자는 설명을 위한 예입니다. 이력서 칸은 `backend/app/schemas.py`의 ResumeIn 기준 (2026-11-17 확인).
