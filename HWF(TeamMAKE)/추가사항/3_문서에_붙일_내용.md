## C-24. 서류 평가 추가 — AI 가 면접 전에 서류 합격·불합격을 정함 (2026-11-17, 사용자 결정)

- 설계 문서(PRD·기능정의서·화면정의서·API 명세서·테이블 정의서·시나리오·플로우차트)에는 서류 평가가 없다. 문서 흐름은 '이력서 제출 → 바로 응시 준비'. 사용자 결정으로 공고마다 켤 수 있는 서류 평가를 더함. 끈 공고(기본값, 기존 공고 전부)는 지금과 같다.
- 루브릭(1안, 수준 기준표형): 기본 60점 + 6개 항목 가산점 40점 — 프로젝트 12 · 기술스택 10 · 경력 8 · 경험 4 · 자격증 4 · 학력 2. 항목마다 0~3단계(학력은 0~2) 기준 문장이 있고 점수 = 단계 ÷ 최고 단계 × 배점. 기술스택 기준은 공고의 필수·우대 기술.
- AI 는 항목마다 따로 불러 단계와 근거 문장만 고른다. 점수·합격 여부는 코드가 계산. 근거 문장이 제출 서류에 없으면 1번 다시, 그래도 없으면 0단계 (면접 채점 T5 는 1점이지만 서류는 근거 없는 점수를 주지 않음). 서류에 그 항목 내용이 없으면 LLM 을 부르지 않고 0단계.
- 판정(사람 없이): 1차(rt, Qwen3-4B) 점수가 합격선 + 2차 구간 이상이면 합격, 합격선 − 구간 미만이면 불합격, 그 사이면 2차(eval, Qwen3-8B)가 처음부터 다시 평가해 그 점수로만 판정. 기본 합격선 75, 구간 5. 구간 0 이면 2차 없음.
- 개인정보: 이름·학교 이름·연락처는 AI 에 넣지 않음(학력은 전공·학위만). 근거 문장에 이력서 글이 들어가 resume_screenings.rounds 는 암호화. 서류 글은 fence 로 감쌈.
- 상태: 서류 평가 중(screening) → 응시 준비(ready) 또는 서류 불합격(screen_rejected). 서류 불합격은 응시하지 않은 끝이라 FINAL_STATUSES·응시 통계·면접 채점 대상이 아님. 마감 때 평가 중이면 미응시 마감. 데이터는 작성 중·준비 중과 같이 공고 1차 결과 공개일 + 7일에 지움.
- 결과는 끝나는 즉시 알림·메일과 마이페이지로 알림(사용자 결정). 지원자는 최종 판정에 쓴 항목별 단계·근거를 보고, 서류 불합격은 1번 이의 신청 가능 → 관리자에게 알림. 관리자는 1차·2차 결과를 모두 보고 판정을 바꿀 수 있음(합격으로 바꾸면 응시 준비 + 질문 만들기 시작, 감사 기록).
- 실행: API 프로세스 안 백그라운드 작업(합격하면 바로 질문 만들기를 시작해야 해서). 1차는 질문 만들기와 같은 LLM 자리(composeSemaphore), 2차는 하나씩. AI 장애면 기록만 남기고 1분 점검이 2분 뒤 다시 시작.
- DB: evaluation_criteria 에 screening_enabled·screening_required_skills·screening_preferred_skills·screening_pass_score·screening_band, 새 표 resume_screenings, applications.attempt_status 값 2개 (migrate).
- 기술스택은 LLM 이 아니라 코드가 공고 기술 이름과 맞춰 단계를 정함 (실측: 4B 가 'Python, SQL' 에서 SQL 을 놓쳐 1단계로 낮춤. CLAUDE.md '단순 조회는 LLM 을 쓰지 않는다'). 이름이 다르게 적힌 같은 기술(파이썬·Python)은 같은 것으로 보지 않음. 1단계 기준을 '필수 기술 절반 미만이거나 우대 기술만'으로 고침(제안 자료에는 '우대 기술만').
- 포트폴리오 PDF(선택, 10MB, 서류 평가 공고만): 이력서와 같은 격리 리더로 글자만 뽑고(글자 없는 PDF 는 앞 3쪽 OCR) 2만 자까지 암호화 저장. 프로젝트·기술스택·경험의 근거로만 씀(앞 2,000자). 지원서 제출 전까지 바꾸거나 지울 수 있고, 파일은 지원 건과 함께 지움.
- 서류 평가를 받은 지원자가 생기면 서류 평가 기준(사용 여부·기술·합격선·구간)은 바꿀 수 없음(SCREENING_STARTED). 다른 평가 기준은 지금 규칙(첫 응시 전까지)대로.
- 실측(이 PC, GTX 1660 SUPER 6GB): 1차 6항목 8.9초(LLM 5번), 2차 117초(8B CPU, LLM 4번). 실제 지원 1건은 제출부터 판정까지 69초(앱 시작 직후).
- 남은 것: 설계 문서(PRD·기능정의서·화면정의서·API 명세서·테이블 정의서·시나리오·플로우차트·AI 아키텍처) 반영, 화면 브라우저 확인, E2E.
