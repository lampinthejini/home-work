옮긴 뒤 꼭 할 일: 컨테이너 다시 만들기

지금 컨테이너는 옛 경로를 기억하고 있습니다. 확인해 보니 llm-rt는 C:\big21\hw-repo\HWF(TeamMAKE)\huge\models를 붙들고 있습니다. 컨테이너가 restart: unless-stopped라서, 그냥 옮기고 PC를 다시 켜면 옛 경로로 다시 뜨다가 모델 파일을 못 찾아 실패할 수 있습니다.

1. 옮기기 전에 컨테이너를 멈춥니다. huge/에서 다음을 실행합니다.
docker compose -f compose.app.yml down
docker compose -f compose.ai.yml down
docker compose -f compose.infra.yml down
   -v는 붙이지 마세요. 붙이면 DB 데이터가 지워집니다.
2. 폴더를 옮깁니다.
3. 새 위치의 huge/에서 sh scripts/up.sh를 실행하면 새 경로로 컨테이너가 다시 만들어집니다.

2. 도커 안에만 있는 데이터

DB(huge-infra_pgdata), 파일 저장소(huge-infra_objectdata, 이력서·녹화 파일), Redis, 모델 캐시는 이 PC의 도커 안에만 있습니다. 폴더를 복사해도 따라가지 않습니다. 둘 중 하나를 고르셔야 합니다.

- A. 새로 시작 (간단): 새 PC에서 처음 설치처럼 띄웁니다. 기본 예비 질문 40개와 회사 정보는 켤 때 자동으로 들어갑니다. 관리자 계정은 python -m app.manage init으로 만듭니다. 공고, 지원자, AI가 쌓은 예비 질문, 회사 소식 제거 기록은 없어집니다.
- B. 데이터도 가져가기: 이 PC에서 DB를 pg_dump로, 파일 저장소 볼륨을 압축 파일로 백업합니다. 새 PC에서 되살린 뒤 **같은 .env**로 띄웁니다. 원하시면 백업·복원 스크립트를 만들어 드릴게요.

3. 새 PC에 있어야 하는 것

- NVIDIA GPU 6GB 이상과 최신 드라이버: 면접 LLM(llm-rt)과 STT가 GPU를 씁니다. GPU가 없으면 이 둘이 안 뜹니다.
- Docker Desktop (WSL2): GPU를 쓰려면 WSL2 백엔드여야 합니다.
- Git Bash: scripts/*.sh를 돌
1. git clone https://github.com/lampinthejini/home-work
2. .env와 models/llm/을 huge/ 안에 넣습니다.
3. huge/에서 sh scripts/fetch-models.sh를 실행합니다(stt·tts·embed·ocr 모델 캐시. LLM 파일을 복사해 왔어도 필요합니다).
4. sh scripts/up.sh
5. A를 골랐으면 docker exec huge-app-api-1 python -m app.manage init, B를 골랐으면 백업 되살리기.
6. 브라우저에서 http://127.0.0.1:8080을 열어 확인합니다.
