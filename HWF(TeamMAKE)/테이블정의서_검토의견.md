# 테이블정의서 검토 의견

- 대상: `테이블정의서.pdf` (2026-10-29, 기준 TRD v1.5 4-1·4-3)
- 검토일: 2026-10-29
- 비교 기준: TRD v1.5 · 화면정의서 v0.5 · API 명세서 v1.1 · 기술아키텍처 v1.1

---

## 0. 총평

TRD 4-1을 충실하게 옮겼고, 공통 규칙(uuid·timestamptz·numeric·_enc 암호화·CHECK·CASCADE)과 ERD, 칸별 설명이 깔끔합니다. 구조 자체에는 큰 문제가 없습니다.

다만 **기준이 TRD뿐**이라서, API 명세서·화면정의서에서 더 정한 값과 칸이 빠져 있습니다. 같은 칸인데 문서마다 값 이름이 다르면 구현할 때 CHECK 제약에서 바로 오류가 나므로 1장은 꼭 맞춰야 합니다.

## 3. 설계상 확인할 것

| # | 내용 | 문제 | 제안 |
|---|---|---|---|
| 3-1 | `users.email` UQ + 탈퇴는 `deleted_at`(소프트 삭제) | 탈퇴한 사람이 같은 이메일로 다시 가입하면 UQ에 걸려 가입 불가 | 탈퇴 시 email·name·phone을 지우거나 가명 처리, 또는 `UNIQUE (email) WHERE deleted_at IS NULL` 부분 인덱스 |
| 3-2 | `consents` 도 지원 건 삭제 때 CASCADE (공통 규칙 6) | 동의 철회 → 응시 데이터 즉시 삭제(APP-03-3)인데, 그때 동의·철회 기록까지 같이 지워져 "언제 동의하고 철회했는지" 증거가 남지 않음 | consents는 CASCADE에서 빼고 `application_id`를 SET NULL, 또는 audit_logs의 `consent` 기록에 문구 버전·시각을 남긴다고 명시 |
| 3-3 | 로그인 실패 횟수가 `users.failed_login_count` | ACC-05: **없는 이메일에도** 같은 실패 횟수·잠금을 적용해야 하는데, 없는 이메일은 users 행이 없음 | 실패 횟수·잠금은 Redis(`login_fail:{email}`)에 둔다고 적고 users 칸은 빼거나 보조용으로 |
| 3-4 | 비밀번호 재설정 링크(30분)·이메일 인증 링크(24시간)·면접 세션 토큰(`sid`)·precheck 통과 표시(15분) | 저장 위치가 어디에도 없음 | 모두 Redis TTL 키라면 "DB에 두지 않음" 한 줄 명시. 재설정 토큰을 DB에 두면 토큰 해시만 저장 |
| 3-5 | `evaluation_criteria.coding_enabled` 기본값 `true` | 코딩테스트는 관리자가 공고별로 켜는 선택 기능 | 화면정의서 S-R03에도 토글 기본값이 적혀 있지 않음. 팀이 기본값(켜짐/꺼짐)을 정해 화면정의서와 테이블정의서에 같이 적기. AI 초안은 질문 12번 답으로 채우므로 영향 없음 |
| 3-6 | `results.decision_check` 의 `rejudged` | AI 판정 검증은 형식·값 범위·근거만 확인하고 합격 기준으로 다시 판정하지 않음(TRD 8-2⑤, 화면정의서 v0.5 D-06) | 값은 그대로 두되 설명을 "형식·근거 검증 실패로 1회 다시 판정함"으로. 합격 기준 불일치 의미로 쓰지 않기 |
| 3-7 | `applications.holds_seat` | 동시 면접 수의 진짜 값은 Redis `interview:active`(TRD 5-3) | DB 칸은 복구·표시용이고 기준은 Redis라고 한 줄 명시 (둘이 어긋날 때 무엇을 믿을지) |

## 4. 작은 것

1. 표지 '기준 문서'에 API 명세서 v1.1·화면정의서 v0.5를 추가하면, 위 1·2장 차이가 왜 생겼는지 읽는 사람이 바로 압니다.
2. PDF에서 칸 이름·설명 줄이 어긋나 보이는 표가 있습니다(4-1, 4-5, 4-13, 4-17~4-19). 원본(엑셀·md)이 있으면 같이 공유하면 구현자가 복사해 쓰기 편합니다.
3. `questions.answer_seconds` 기본 90은 기본 질문 기준이므로, 꼬리질문 60초는 `interview_questions.answer_seconds`에 들어간다는 점을 설명에 적어 두면 좋습니다.
